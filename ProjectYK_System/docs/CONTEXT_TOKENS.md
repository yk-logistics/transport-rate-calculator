# Context / Token — แยก “แชต” กับ “กฎ/เครื่องมือ” กับ “ไฟล์ใน repo”

เอกสารสั้นสำหรับทีมและ Agent: **อะไรกิน token ใน Cursor มากที่สุด** และอะไรไม่โตตามเวลาคุย

## ถัง (buckets) ใน UI Context ของ Cursor

| ถัง | ความหมายโดยประมาณ | โตแบบไหน |
|-----|-------------------|----------|
| **Conversation** | ประวัติข้อความใน **เธรดเดียว** + ผลลัพธ์จากเครื่องมือที่ฝังในแชต | **โตเร็ว** เมื่อคุยยาว / แปะ log ยาว / รันคำสั่งที่เอาต์พุตยาวหลายรอบ |
| **Rules** | กฎโปรเจกต์ใน `.cursor/rules/` ที่โหลดตามการตั้งค่า | ค่อนข้างคงที่ต่อเซสชัน |
| **Tools** | คำอธิบายความสามารถของเครื่องมือ (อ่านไฟล์, เทอร์มินัล ฯลฯ) | ค่อนข้างคงที่ |
| **Skills** | Skill ที่เปิดใช้ | มักเล็กเมื่อเทียบกับ Conversation |
| **System / MCP** | พรอมต์ระบบและ MCP | ค่อนข้างคงที่ |

**สรุป:** ถ้าต้องการประหยัด context — **ตัด Conversation** เป็นหลัก (แชตใหม่, scope เดียว, ไม่แปะ log ยาว)

## ไฟล์ใน repo กับ token

เมื่อ Agent **เปิดอ่านไฟล์** ผ่านเครื่องมือ เนื้อหานั้นจะเข้า **รอบการทำงานนั้น** — ไม่ใช่ “Rules” แต่ถ้าอ่านไฟล์ยาวซ้ำๆ ในเธรดเดียว ก็จะกินงบ context ของเธรดนั้น

ดังนั้นนโยบายใน `ProjectYK_System/docs/CHANGELOG_POLICY.md` และกฎใน `.cursor/rules/project-yk-context.mdc` จึงจำกัดว่า **CHANGELOG / CONTEXT_LOG อ่านแค่ช่วงที่จำเป็น**
