# Performance Checklist รอบแรก (วัดง่าย ใช้ได้ทันที)

เอกสารนี้ใช้วัด "ก่อน-หลัง" แบบไม่ซับซ้อน เพื่อให้ตัดสินใจได้เร็วว่างานปรับประสิทธิภาพคุ้มหรือยัง

## เป้าหมายรอบแรก (ใช้เวลา 15-30 นาที)

- ลดเวลาเริ่มลงมือ (AI เริ่มแก้ไฟล์แรกเร็วขึ้น)
- ลดจำนวนรอบถามกลับโดยไม่จำเป็น
- ลด token ต่อหนึ่งงานย่อย

## A) เก็บ baseline ก่อนปรับ (งานจริง 1 งาน)

- [ ] เลือกงานเล็ก 1 งานที่ทำซ้ำได้ (เช่น แก้ UI จุดเดียว)
- [ ] บันทึก 3 ค่า:
  1) Time to first code change (นาที)
  2) Token used
  3) Clarification rounds
- [ ] บันทึกลง `ProjectYK_System/tools/CC_BENCHMARK_LOG.md` (Run #1)

## B) ปรับรอบแรก (ใช้วิธีที่ตกลงแล้ว)

- [ ] รันงานเล็กถัดไปด้วย `ULTRA-LEAN` template
- [ ] ถ้าถามกลับเกิน 1 รอบ หรือเริ่มช้าเกิน 10 นาที ให้สลับ `LEAN` ทันที
- [ ] บันทึกผล Run #2 และ Run #3 ในไฟล์ benchmark เดิม

## C) สรุปผลแบบตัดสินใจได้

หลังครบอย่างน้อย 3 runs:

- [ ] ถ้า `ULTRA-LEAN` เร็วกว่าและถามกลับน้อยกว่า -> ใช้เป็น default งานเล็กต่อ
- [ ] ถ้า `ULTRA-LEAN` fail/ถามกลับบ่อย -> เปลี่ยน default เป็น `LEAN`
- [ ] งานเงิน/import/payroll -> บังคับ `careful` เสมอ (ไม่เข้า benchmark กลุ่มงานเล็ก)

## D) วิธีวัดก่อน-หลังแบบสั้น (template copy)

```text
งาน: <ชื่องาน>
โหมด: ultra-lean | lean | careful
ก่อนปรับ: เริ่มแก้ไฟล์ <x> นาที | token <y> | ถามกลับ <z> รอบ
หลังปรับ: เริ่มแก้ไฟล์ <x2> นาที | token <y2> | ถามกลับ <z2> รอบ
ผลต่าง: เวลา <...> | token <...> | รอบถามกลับ <...>
ตัดสินใจ: ใช้โหมด <...> เป็น default สำหรับงานประเภทนี้
```

## E) Guardrail กันหลงประเด็น

- วัดทีละ 1 ตัวแปร (อย่าปรับหลายอย่างพร้อมกันใน run เดียว)
- ใช้งานจริงก่อนเชื่อผล (หลีกเลี่ยงงานทดลองที่ไม่เหมือนหน้างาน)
- ถ้าเสี่ยงข้อมูลเงินตกหล่น ให้หยุด benchmark แล้วกลับโหมดรอบคอบทันที
