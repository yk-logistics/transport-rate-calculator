## 3. กฎเงินเดือนและรอบตัดจ่าย (สรุปสั้น)

จาก Session **#8**, **#9** — รายละเอียดตัวเลขและ edge case ครบใน `SITE_PAYROLL_RULES.md`

**รอบตัดจ่าย (lock ในระบบ / แผน):**

- **BIGC** — ตัด 1–สิ้นเดือน, จ่ายวันที่ 1 เดือนถัดไป  
- **LCB** — ตัด 16–15, จ่ายวันที่ 1 เดือนถัดไป  
- **AYU** — ตัด 26–25, จ่ายสิ้นเดือน  

**ทั่วไป:** เงินประกันตน 10,000 หัก 1,000/เดือน, ประกันสังคม ~5% ฐาน 9,000, เบิก/หักจากสดย่อย, อุบัติเหตุ 2,000 ผ่อน 500×4  

**BIGC:** ฐาน 9,000 + ค่าเที่ยว + เรทน้ำมันเหลือคืน `(target − actual) × 16`  

**LCB** สองโหมด: รายเที่ยว (9240 + ดูแลรถ 3000 + เที่ยว / หักรายวันเมื่อลา) vs เหมาน้ำมัน (เช่น 60% ค่าขนส่ง; บางค่าลูกค้าไม่แบ่ง)  

**AYU** สองโหมด: รายเที่ยว (การันตี 12k/15k ตามประเภท) vs เหมาน้ำมัน 55–60% ตามสัญญารายคน  

**คำตอบที่ล็อกแล้ว (Session #9):**  
- LCB หักรายวันแยก `9240/30` + `3000/30`  
- การันตี AYU = เพดานเต็มเดือน หักตามวันลา/ไม่มา  
- Cross-site payroll ใช้ **ไซต์หลักของคนขับ**; ค่าเที่ยวข้ามไซต์ช่วงแรกให้ **กรอกได้** ไม่บังคับสูตร  
- ทุก role **เห็นทุกไซต์** (filter ใน UI)  
- **Line OA ยังไม่ทำ** — ใช้ copy ไปกลุ่มไลน์ก่อน

## 7. เคสเสนอราคา Direct-to-store (ตัวอย่างลูกค้า)

จาก Session **#52–#56** (2026-04-28) — ไฟล์ทำงาน Excel เฉพาะดีล (เช่น Thainumtip/Lotus) มีการปรับหลายรอบ

ข้อที่ถือเป็น **นโยบายเจรจาการคุย** (ไม่ใช่ตัวเลขล็อกของทั้งบริษัท):

- Maintenance ~1.5 บาท/กม., back office ~12%, เสนอราคา floor แยก 6W/10W, ปัดเป็นหลักร้อย  
- Consumption แยก 6W / 10W (ค่าที่ใช้ในไฟล์ดีล เช่น ~5.0 และ ~4.5 กม./ลิตร ในรอบสุดท้าย)  
- **ปรับราคาตามราคาน้ำมัน:** ใช้สัดส่วนต่อ 1 บาท — รอบหนึ่งวิเคราะห์ว่า `2% ต่อ 1 บาท` ไม่ครอบทุกรูทที่น้ำมัน 50; ทีมปรับเป็น **`1.5% ต่อ 1 บาท`** ตามที่โอยืนยัน พร้อมปรับ base ให้ยังอยู่ใน margin เป้า  
- โซน **สมุทรปราการ / ฉะเชิงเทรา / ชลบุรี** อนุญาต margin ต่ำกว่า (เป้า ~5%) เพื่อชิงงาน — โซนอื่น ~10%  
- ค่าเที่ยวแบบขั้นบันไดตามระยะ (0–200 กม. แล้วบวกทุก 100 กม.)  

รายละเอียดเซลล์/สูตรใน Excel — อ้างไฟล์ดีลจริงใน `data/` หรือโฟลเดอร์ลูกค้าเมื่อทำซ้ำ

สรุปเฉพาะข้อตกลงที่กระทบ **ความหมายเงินกับลูกค้า** — รายละเอียดโค้ดใน `Oatside/` และสเปก `OATSIDE_*`

**เรทฐานเที่ยว (ยกตัวอย่างรอบเม.ย. 2026):** วันที่ **12–15 เม.ย.** เรท **8,000** บาท; วันอื่น **7,500** (อ้าง `Dest_In`) — Session **#75**, และยืนยัน base fuel band ใน session #166–167  

**ชาร์จ 50% วันละ 1 เที่ยว:** ถ้าวันนั้นต่อทะเบียนต่อวันปลายทางมี **1 matched trip** ให้บวก **50% ของเรทวันนั้น** — มีไฟล์ override JSON (`oatside_billing_overrides`) เพื่อกันเคสความจริงไม่ตรงระบบ — Session **#74**  

**ไม่เก็บค่าชดเชยเที่ยวขาดขั้นต่ำ** พร้อมกับชาร์จ 50% ได้ — config `charge_min_trip_shortfall` default **false** — Session **#77**  

**กรอบ 24 ชม. / วันงาน / ฝากรถ:** Session **#90–#94** — รวมถึงเคส **71-8967 @ P&G**: ช่วงฝากรถในโรงงานลูกค้า **ไม่คิด dwell / ไม่เตือน 50% จาก GPS ในช่วงนั้น** เมื่อตั้งค่าใน config (`customer_idle_windows` / `parked_at_customer`)  

**จำนวนเที่ยวต่อวัน (มุมลูกค้า):** นับ matched ตามวัน **Dest_In** — Session **#89**  

**หมายเหตุ:** มีการยืนยัน **12–15 เม.ย. = 8,000** ภายใต้ base fuel band เฉพาะช่วง (ดู CONTEXT_LOG session #166)

## 13. การตัดสินใจที่เคยเปิด (อัปเดตจากโอ — 2026-05-08)

รายละเอียดเชิงฟิลด์/สูตรอยู่ใน [`SITE_PAYROLL_RULES.md`](../TransportRateCalculator/docs/SITE_PAYROLL_RULES.md)

### LCB Mode B — รายการ “ไม่แบ่ง” กับคนขับ

- **ไม่บังคับล็อกลิสต์ค่าธรรมเนียมครบทุกประเภทในระบบเดียว** เพราะข้อตกลงลูกค้าเปลี่ยนได้และตายตัวยาก  
- **แนวทาง:** ให้ **ผู้ใช้ระบุเอง (manual)** ว่ารายการไหนไม่เข้าฐานหารกับคนขับในเที่ยว/สัญญานั้น  
- **ครั้งถัดไป:** ระบบควร **จำค่าที่เคยเลือก** (เช่น preset ต่อลูกค้า/ประเภทงาน หรือแนะนำจากครั้งก่อน) — รอออกแบบฟิลด์ในแอป

### ประกันสังคม — ฐานคำนวณ

- **แล้วแต่คน** — ไม่ใช่คำตอบเดียวทั้งบริษัท  
- **แนวทาง:** ให้ **ผู้ใช้เลือกตอนลงทะเบียนคนขับ** (หรือในฟอร์มสัญญา) เช่น โหมด **ฐาน 9,000 คงที่** vs **ตามฐานเงินเดือนจ่ายจริงรายคน** — รอฟิลด์ใน Employee / contract

### BIGC โค้ด `1DH` — คำถามเดิมหมายถึงอะไร

คำถามเดิมหมายถึง: **ตอนออกบิลลูกค้า / คิดค่าขนส่งในแถวประเภท `1DH`** ให้คิดแบบไหนถึงจะ “จบงาน” ตรงกับที่ทีมใช้ใน Daily  

คำตอบที่ล็อกไว้แล้วใน Session **#9** + ตารางใน `SITE_PAYROLL_RULES.md`: **`1DH` = direct backhaul — คิดค่าขนส่งลูกค้าแบบสาขาเดียว** (ใช้เรทตามปลายทาง/สาขานั้น) ไม่มีการพ่วงหลายสาขาแบบ `1+` / `2++` และในแถวตารางเดิม **ไม่มีค่าเที่ยวคนขับแยกในช่องประเภทนี้** (เหมือนโครงที่ใช้อยู่ในตาราง BIGC)

- **คำยืนยันจากโอ (2026-05-08):** **`1DH` = สาขาเดียว** (ใช้เรียกสั้นๆ ได้ตรงกับข้อความใน Daily)

ถ้าต้องการความละเอียดบรรทัดบิลล์จริงในอนาคต — ผูกจากเมนู **Daily / ใบงาน** เดียวกับที่บัญชีใช้ออกบิล

### LINE / Line OA

- **ไม่แยกเป็นโครงการใหม่** — ถือเป็น **โครงเดียวกับ One Platform** ตามเฟสใน `AGENTS.md` (เฟส 5 Line OA เป็นต้น)  
- **ไม่ปะปนกับ “ยังไม่ทำ integration”** แบบเดิมได้โดยใช้แค่ **phase/milestone** ในแผน (`NEXT_ACTION_PLAN`) ไม่ต้องมี repo หรือโปรเจกต์แยก
