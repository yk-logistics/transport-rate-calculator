# PAY_ADJUSTMENT_RUNBOOK — ระบบค่าเที่ยวตกหล่น/จ่ายตามหลัง (C4)

> ทำเมื่อ 3 ก.ค. 2026 · สำหรับคน/โมเดลเด็กทำเคสจริงได้โดยไม่ต้องคิดใหม่
> ปัญหาที่แก้: ลูกค้าบางเจ้ารู้ราคาจริงช้า — รอบเงินเดือน finalize ไปแล้ว
> (**ห้าม recompute รอบ finalized — สดย่อยจะหาย** บั๊กที่รู้กันแล้ว) → ต้องจ่ายเพิ่ม/หักคืนรอบถัดไป

## ใช้ยังไง (เคสปกติ — อัตโนมัติทั้งสาย)

1. โอ/ทีมแก้ **ค่าเที่ยว (trip_fee_driver)** ของแถวในหน้า /daily ตามราคาจริงที่เพิ่งรู้ → กด Save Grid ตามปกติ
2. ถ้าแถวนั้นอยู่ในช่วงของรอบที่ **finalize แล้ว** ระบบตั้ง "ยอดตกหล่น" ให้เอง (Δ = ใหม่−เก่า, + จ่ายเพิ่ม / − หักคืน) — ข้อความหลัง Save บอกว่า "ตั้งยอดตกหล่นรอบปิดแล้ว X รายการ"
3. ยอดค้างเห็นได้ที่หน้า /payroll/<รอบ> กล่องฟ้า "ค่าเที่ยวตกหล่นรอรอบถัดไป" — กด **ยกเลิก** ได้ตราบใดที่ยังไม่ถูกดูดเข้ารอบ
4. พอคำนวณรอบใหม่ (รอบต้องจบทีหลังรอบต้นเหตุ + ไซท์เดียวกัน) engine บวกเข้า **รายได้อื่น** (+) หรือ **หักอื่น** (−) ของคนนั้นเอง + จด "ตกหล่นจากรอบก่อน" ใน note + กล่องเขียวบนหน้ารอบสรุปว่ารายการไหนถูกดูดแล้ว

## กติกาภายใน (แก้โค้ด/ตรวจบั๊กอ่านตรงนี้)

- ตาราง `PayAdjustment` (v36): amount +/-, status pending→applied (หรือ cancelled), source_run_id=รอบต้นเหตุ, applied_run_id=รอบที่จ่ายจริง
- engine hook: `services/payroll.py: _apply_pay_adjustments()` เรียกใน `compute_pay_run` ต่อคนก่อน add item
- **idempotent**: recompute รอบเดิมซ้ำ → ดูดชุดที่ applied กับรอบนั้นกลับมาใหม่ (ไม่ double ไม่หาย); เทสต์คุมอยู่
- **ไม่ดูดเข้ารอบเก่า**: pending เข้าเฉพาะรอบที่ period_end ใหม่กว่ารอบต้นเหตุ (กันรอบ draft เก่าค้างดูดไปผิดรอบ)
- ทำไมดู trip_fee_driver อย่างเดียว: engine จ่ายจาก Σ trip_fee_driver ทุก pay_mode (เหมาก็ใช่ — fix 30 มิ.ย.) ราคา (revenue) มีผลฝั่งบิล ไม่ใช่เงินคนขับ
- สร้างมือ (เคสพิเศษ ไม่ผูกเดลี่): ใส่แถว `PayAdjustment` ตรงๆ ผ่าน ORM — employee_id, site_code, source_run_id (รอบต้นเหตุ), amount, reason ให้ครบ
- คนที่ไม่มีเดลี่ในรอบใหม่เลย: engine ข้ามคน → pending **ค้างรอ** ไปรอบถัดไปอีก (ไม่หาย) — ถ้าคนออกไปแล้วต้องเคลียร์เงินให้ทำมือ

## วิธีตรวจย้อนกลับ (หลังเคสจริงเคสแรก)

1. ก่อนคำนวณรอบใหม่: `tools/net_guard.py before` → คำนวณ → `after --allow <run_id>` — ต้องขยับเฉพาะรอบที่ตั้งใจ
2. ยอดที่ขยับต้อง = Σ pending ที่โชว์ในกล่องฟ้าก่อนคำนวณ (บวกลบตามเครื่องหมาย)
3. เปิดสลิปคนนั้น: รายได้อื่น/หักอื่น ต้องรวมยอด + note มี "ตกหล่นจากรอบก่อน"
4. ตาราง: `select * from payadjustment where status='applied' and applied_run_id=<run>` ต้องตรงกับกล่องเขียวบนหน้ารอบ
