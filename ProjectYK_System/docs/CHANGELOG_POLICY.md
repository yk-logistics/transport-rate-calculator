# นโยบาย CHANGELOG / CONTEXT_LOG (โตตามเวลา — ลดการอ่านซ้ำ)

## เป้าหมาย

- **CHANGELOG_MASTER.md** ยังเป็นที่ **append** การตัดสินใจข้ามโมดูล
- Agent **ไม่ควรอ่านทั้งไฟล์** ทุกแชต (ไฟล์ยาวขึ้นเรื่อยๆ → เสีย token เปล่า)
- เรายังคงประวัติเต็มใน git — แค่ **ลำดับการอ่าน** ของ Agent จำกัดขอบเขต

## CHANGELOG_MASTER.md

1. **ตอน bootstrap (ทุกแชต):** อ่าน**เฉพาะหัวข้อล่าสุดไม่เกิน 3 หัวข้อ** ระดับ `##` ที่บรรทัดต้นๆ หลังส่วนหัว (รูปแบบ `## YYYY-MM-DD (...)` หรือหัวข้อตัดสินใจล่าสุด) — เพียงพอรู้ว่า “เพิ่งตกลงอะไร”
2. ถ้างานต้องใช้ประวัติยาว (สืบเหตุ, audit): ใช้ค้นหาใน repo (`rg` / grep) หรือเปิดอ่านบางช่วงที่มีคีย์เวิร์ด — **ไม่**ดึงทั้งไฟล์มาวางในแชต
3. **Archive (ทำเมื่อไฟล์หนักเกิน ~800–1000 บรรทัด หรือตามรอบไตรมาส):**  
   - คัดช่วงเก่าที่ปิดแล้วไปไว้ใน `ProjectYK_System/docs/CHANGELOG_ARCHIVE/` (ชื่อไฟล์เช่น `CHANGELOG_2025_Q4.md`)  
   - ใน `CHANGELOG_MASTER.md` เหลือเฉพาะช่วงล่าสุด + บรรทัดลิงก์ไป archive

รายการ index ของไฟล์ archive: [CHANGELOG_ARCHIVE.md](CHANGELOG_ARCHIVE.md)
