# RM History Backfill — ดึงประวัติซ่อม 2018-2026 จาก Google Sheets เข้าระบบ

> สเปคออกแบบ · 9 ก.ค. 2026 · โอเคาะแล้วทั้ง 8 ข้อ (ก่อนแตะโค้ด)

## 1. ปัญหา

ประวัติซ่อมบำรุงรถทั้งหมดตั้งแต่ปี 2018 อยู่ใน Google Sheets 3 ไฟล์ (แยกตามไซท์
แยกแท็บตามทะเบียนรถ) — ทีมพิมพ์ไว้ครบแล้ว แต่ระบบ MVP มี `maintrecord` แค่ **1 แถว**
ทำให้ตอบคำถามพื้นฐานไม่ได้: คันไหนซ่อมแพงสุด · อะไหล่ตัวไหนเปลี่ยนบ่อย · ร้านไหนคิดแพง

**ข้อมูลนี้ไม่ต้องใช้ OCR** — มันถูกพิมพ์ไว้แล้ว ดึงเข้าตรงๆ แม่นกว่าและไม่กินโควต้า AI
(OCR เก็บไว้ใช้กับบิลใบใหม่ที่ยังไม่มีใครพิมพ์)

## 2. ข้อมูลต้นทาง (สแกนจริง 9 ก.ค. 2026, read-only)

|------|------------|--------|-----|--------------|
| `RM History(BigC Thanya)` | 20 | 18 | 2,974 | 6,211 |
| `RM History(Wangnoi)` | 50 | 47 | 3,298 | 6,724 |

```
แถว 20: รายการซ่อมรถ | | | |  140,457.00 | 167,433.10 | 40,277.25 | 6,419.97 | 133,575.82   ← ยอดรวมที่ชีทคำนวณเอง

แถว 23: 13/05/20 | 12,029 | Isuzu บางปะอิน | บริการพ่นน้ำยาฆ่าเชื้อ | 1.00 | - | - | | - | -
แถว 24:          |        |                | น้ำกลั่น              | 1.00 | 10.00 | 10.00 | | 0.70 | 10.70
```

**ข้อเท็จจริงที่ทำให้ import พังถ้าไม่รู้ก่อน:**

1. **หัวตารางอยู่คนละแถวกันในแต่ละแท็บ** — พบตั้งแต่แถว 1 ถึงแถว 22 → ต้อง**ค้นหา**แถวที่
   คอลัมน์แรกเป็น `"วันที่"` ห้ามล็อกเลขแถว
2. **วันที่ปน พ.ศ. กับ ค.ศ. ในไฟล์เดียวกัน** — `13/05/20`, `18/02/2021`, `.../66`, `/67`, `/69`
3. **บางแท็บไม่ใช่รถ** — `หน้ารวม`, `ชีต3`, `เช็ครถประจำเดือน`, `แบตเตอรี่`, `Stock ยาง`,
   `รับรถ 8682`, `ตู้1..5` และทะเบียนบางแท็บเขียน `71-6802 อย`, `72-2294(หางใหม่)`
4. **วันที่ว่าง = บรรทัดต่อของบิลใบเดิม** (fill-down) — ไม่ใช่บิลใหม่
5. **สูตรเงินยืนยันแล้ว:** `(รวม − ส่วนลด) × 1.07 = ราคาสุทธิ` (พิสูจน์: `(690 − 103.50) × 1.07 = 627.56` ตรงช่องในชีท)

## 3. ขอบเขต

**ทำ:** ตารางประวัติซ่อมรายคัน → `MaintRecord` + `MaintPart` (โครง v49)

**ไม่ทำรอบนี้:**
- แท็บ `Stock ยาง` / `แบตเตอรี่` / `เช็ครถประจำเดือน` (เฟสถัดไป)
- บล็อก "ยางปัจจุบัน" ในแท็บรถ → ไปรวมกับงาน "ช่างลงทะเบียนยางรอบแรก"
- **ปุ่มบนหน้าเว็บ** — งานย้อนหลังทำครั้งเดียว ใช้สคริปต์ + `--dry-run` พอ
  (ปุ่มเก็บไว้ให้งานที่ทำซ้ำ เช่น ดึงเดลี่ AYU)

**ข้อจำกัดที่รู้ตัว:** ทุกบิลที่ import จะได้ `kind="repair"` — ยังไม่แยก `tire_change`
อัตโนมัติ (คำว่า "ยาง" ในรายการอาจเป็นยางแท่นเครื่อง/ยางกันกระแทก) ค่อยทำ pass แยกทีหลัง
เมื่อมีข้อมูลยางรายเส้นแล้ว

## 4. สถาปัตยกรรม

แยก **ตรรกะการแปลง** (ทดสอบได้ ไม่แตะ DB/เน็ต) ออกจาก **การเขียน DB** ชัดเจน

### 4.1 `services/rm_history.py` — pure functions

| ฟังก์ชัน | หน้าที่ | คืนค่า |
|---------|--------|--------|
| `parse_date(raw) -> date \| None` | แปลงวันที่ตามกฎข้อ 5 | `None` = อ่านไม่ออก (ห้ามเดา) |
| `normalize_plate(tab_title) -> str \| None` | `"71-6802 อย"` → `"71-6802"` | `None` = ไม่ใช่แท็บรถ |
| `classify_kind(detail) -> "part"\|"labor"\|"service"` | จัดหมวดบรรทัด | ค่าเริ่มต้น `part` |
| `parse_tab(tab_title, values) -> ParsedTab` | หา header row → รวมบรรทัดเป็นบิล (fill-down วันที่) | `bills[]` + `issues[]` |

`ParsedTab.bills[i]` = `{work_date, mile, vendor_name, lines[], sheet_row}`
`ParsedTab.issues[i]` = `{row, reason, raw}` — ทุกแถวที่ข้ามต้องมีเหตุผลบันทึกไว้

### 4.2 `services/rm_history_import.py` — แตะ DB

```
import_tab(session, sheet_id, tab, parsed, dry_run) -> Stats
```
- `dry_run=True` → นับอย่างเดียว ไม่เขียนอะไร (ค่าเริ่มต้นของสคริปต์)
- หา/สร้าง `Vendor` จากชื่อร้าน (normalize ช่องว่าง) — รายชื่อร้านใหม่ต้องพิมพ์ในรายงาน
- สร้าง `MaintRecord` + `MaintPart` ตามข้อ 6

### 4.3 `tools/import_rm_history.py` — CLI

```bash
python tools/import_rm_history.py --dry-run              # รายงานอย่างเดียว (ค่าเริ่มต้น)
python tools/import_rm_history.py --apply --file lcb     # เขียนจริง ทีละไฟล์
python tools/import_rm_history.py --rollback --file lcb  # ลบทั้งชุดของไฟล์นั้น
```

อ่านชีทด้วย service account เดิม (`noble-history-*.json`, secret #7) แบบ `values_batch_get`
(1 API call ต่อไฟล์ — โควต้า 60 reads/min)

## 5. กฎแปลงวันที่ (ห้ามเดา)

| รูปแบบปี | กฎ | ตัวอย่าง |
|---------|-----|---------|
| 4 หลัก ≥ 2500 | ลบ 543 | `2566` → 2023 |
| 4 หลัก 1990-2100 | ใช้เลย | `2021` → 2021 |
| 2 หลัก 60-79 | พ.ศ. → `2500+xx−543` | `/67` → 2024 |
| 2 หลัก 15-40 | ค.ศ. → `2000+xx` (ข้อมูลบริษัทเริ่ม 2018) | `/20` → 2020 |
| อื่นๆ | **`None` + บันทึก issue** | `/29`, `/02` |

เพิ่มด่านสุดท้าย: **วันที่ในอนาคต (> วันนี้) = ไม่รับ** บันทึกเป็น issue

## 6. โมเดลเงิน (schema v50)

ชีทมี 5 ช่อง: `ราคา (unit)` `รวม (sum)` `ส่วนลด` `VAT` `ราคาสุทธิ (net)` — ระบบเรามีแค่ 3 ช่องยอด

**เพิ่มคอลัมน์ (ALTER additive, default 0):**

| ตาราง | คอลัมน์ใหม่ |
|-------|-----------|
| `MaintPart` | `discount`, `vat` |
| `MaintRecord` | `discount`, `vat`, `import_key` |

**gotcha SQLite:** `ALTER TABLE ... ADD COLUMN ... UNIQUE` ทำไม่ได้ → เพิ่มคอลัมน์ธรรมดา
แล้วสร้าง index แยก: `CREATE UNIQUE INDEX IF NOT EXISTS ux_maintrecord_import_key
ON maintrecord(import_key) WHERE import_key != ''` (partial index — แถวเดิมที่ค่าว่างไม่ชนกัน; ห้ามตั้งชื่อ ix_ เพราะชนกับ index ที่ SQLModel สร้างเอง)

**กติกายอด (แก้ `_recompute_maint_costs`):**

```
line.total  = qty × unit_price          (ก่อนหักส่วนลด ก่อน VAT — ตรงช่อง "รวม")
parts_cost  = Σ line.total ที่ kind=part
labor_cost  = Σ line.total ที่ kind=labor
other_cost  = Σ line.total ที่ kind=service
discount    = Σ line.discount
vat         = Σ line.vat
total_cost  = (parts + labor + other) − discount + vat     ← เงินที่จ่ายจริง
```

บันทึกเดิมทั้งหมดมี `discount = vat = 0` → `total_cost` ได้ค่าเดิมเป๊ะ **ไม่มี regression**
(ต้องมีเทสต์ยืนยันข้อนี้)

## 7. จับคู่รถ

`normalize_plate()`: ตัด `" อย"`, `"(หางใหม่)"`, ช่องว่างซ้ำ → เทียบ `Vehicle.plate_no`

- จับคู่ได้ → `MaintRecord.vehicle_id` + `plate_raw`
- **จับคู่ไม่ได้ → ไม่ import แท็บนั้นทั้งแท็บ** พิมพ์ชื่อแท็บในรายงานให้โอตัดสิน
  (ห้ามสร้าง `MaintRecord` ลอยที่ไม่ผูกรถ — ค่าซ่อมจะไปโผล่ในรายงานรวมโดยไม่มีเจ้าของ)

## 8. บรรทัดราคา 0

รายการตรวจเช็คของศูนย์ ("ตรวจแผ่นกรองอากาศ", "อัดจารบีช่วงล่าง") **เก็บไว้**
เป็น `MaintPart(kind="service", qty=1, unit_price=0, total=0)` — คือประวัติการบำรุงรักษา
ไม่กระทบยอดเงินสักบาท

## 9. ยิงซ้ำไม่เกิดซ้ำ + ย้อนกลับได้

```
MaintRecord.import_key = f"rm:{file_slug}:{sha1(f'{sheet_id}|{tab}|{first_row}')[:16]}"
                          เช่น  rm:lcb:9f2a1c4b7e0d3a55
```

ขึ้นต้นด้วย `rm:<file_slug>:` **เพื่อให้ rollback กรองด้วย prefix ได้** (ถ้าใช้ sha1 ล้วน
จะกรองตามไฟล์ไม่ได้เลย)

- รันซ้ำ → เจอ key เดิม = **ข้าม** (idempotent) นับใน `stats["skipped"]`
- `--rollback --file lcb` → ลบ `MaintRecord` ที่ `import_key LIKE 'rm:lcb:%'` พร้อม
  `MaintPart` ลูก; ต้องพิมพ์จำนวนแถวที่จะลบและถามยืนยันก่อน (เว้นแต่ใส่ `--yes`)
- บันทึกที่คนคีย์เองมี `import_key = ""` → **ไม่มีวันโดนลบจาก rollback**

## 10. การตรวจทาน (เกณฑ์ผ่าน) — แก้ 9 ก.ค. หลังพบว่ายอดสรุปในชีท "ค้าง"

**สิ่งที่ค้นพบตอนลอง parser กับแท็บจริง:** ช่องยอดรวมของชีทเป็น `=SUBTOTAL(9, J23:J205)`
คือ **ล็อกช่วงแถวไว้ตายตัว** แต่ทีมเพิ่มแถวลงไปเรื่อยๆ โดยไม่ขยายสูตร

| ทะเบียน | สูตรบวกแค่ | ชีทโชว์ | ข้อมูลจริงถึงแถว | ยอดจริง |
|---------|-----------|---------|-----------------|---------|
| 71-6802 | J23:J205 | 133,575.82 | 393 | ~231,688 |
| 71-6803 | J23:J148 | 14,793.41 | 600 | **161,523.33** (11 เท่า) |

→ **ยอดบนหน้าชีทใช้เป็น ground truth ทั้งแท็บไม่ได้** แต่ใช้พิสูจน์การอ่านคอลัมน์ได้

**เกณฑ์ผ่าน 2 ชั้น:**

1. **ชั้นพิสูจน์การอ่าน (บังคับ):** อ่านสูตรจริง (`valueRenderOption=FORMULA`) → ดึงช่วงแถว
   `J{lo}:J{hi}` → บวก `ราคาสุทธิ` เฉพาะแถวในช่วงนั้น **ต้องตรงกับตัวเลขที่ชีทโชว์ ±0.01 ทุกคัน**
   (พิสูจน์แล้วกับ 71-6803: ได้ 14,793.41 ตรงเป๊ะ)
2. **ชั้นรายงาน:** พิมพ์ยอดจริงทั้งแท็บ + ส่วนต่างจากที่ชีทโชว์ ให้โอเห็นว่าค่าซ่อมจริง
   สูงกว่าที่เคยเห็นเท่าไหร่ (ไม่ใช่เกณฑ์ผ่าน/ไม่ผ่าน)

**บรรทัดที่ชีทไม่ได้กรอกช่อง "ราคาสุทธิ" (โอเคาะ 9 ก.ค.):** ยังนับเป็นค่าซ่อม โดยคำนวณ
`รวม − ส่วนลด + VAT` (71-6802 มี 17 บรรทัด = 12,161.90 บาท) — รายงานต้องพิมพ์จำนวน/ยอดให้เห็น

## 12. เทสต์ (TDD — เขียนให้แดงก่อน)

**หน่วย (`services/rm_history.py`)**
1. `parse_date`: `13/05/20`→2020-05-13 · `18/02/2021`→2021-02-18 · `01/03/67`→2024-03-01 ·
   `2566`→2023 · `/29`→`None` · วันที่อนาคต→`None`
2. `normalize_plate`: `71-6802 อย`→`71-6802` · `72-2294(หางใหม่)`→`72-2294` ·
   `หน้ารวม`/`ตู้1`→`None`
3. `classify_kind`: `ค่าแรงถอดยาง`→labor · `บริการพ่นน้ำยา`/`ตรวจแผ่นกรอง`→service · `น้ำกลั่น`→part
4. `parse_tab`: header อยู่แถว 17 ก็เจอ · วันที่ว่าง = บรรทัดต่อของบิลเดิม (1 บิล 9 บรรทัด) ·
   แถวขยะเข้า `issues` พร้อมเหตุผล

**เงิน (`_recompute_maint_costs`)**
5. บันทึกที่มี discount/vat: `(690 − 103.50) + 41.06 = 627.56`
6. **regression:** บันทึกเดิมที่ discount=vat=0 → `total_cost` เท่าเดิมทุกบาท

**import**
7. `dry_run=True` → DB ไม่เปลี่ยนแม้แต่แถวเดียว
8. รัน `import_tab` สองครั้ง → จำนวนบิลเท่าเดิม (idempotent)
9. แท็บที่จับคู่รถไม่ได้ → 0 record + มี issue

**e2e (ข้อมูลจริง, DB ชั่วคราว)**
10. import 1 แท็บจริงจากชีท LCB → ยอดสุทธิรวมตรงกับยอดในชีท

## 13. ความเสี่ยง

| ความเสี่ยง | กัน |
|-----------|-----|
| แปลงปีผิด → ค่าซ่อมไปโผล่ผิดปี | กฎข้อ 5 + ปฏิเสธวันอนาคต + รายงาน issue |
| ยิงซ้ำ → ค่าซ่อมเบิ้ล | `import_key` unique + `--dry-run` เป็นค่าเริ่มต้น |
| จับคู่รถผิดคัน | ตัด suffix แล้ว match ตรงตัวเท่านั้น จับไม่ได้ = ไม่ import |
| ร้านซ้ำเพราะสะกดต่าง | normalize ช่องว่าง + พิมพ์รายชื่อร้านใหม่ให้โอตรวจก่อน `--apply` |
| ทำลายยอดของบันทึกเดิม | เทสต์ regression ข้อ 6 + production มี maintrecord แค่ 1 แถว (ยอด 0) |
| ชีทถูกแก้ระหว่าง import | อ่านทั้งไฟล์ครั้งเดียวด้วย `values_batch_get` |

## 14. ลำดับลงมือ

1. schema v50 + `_recompute_maint_costs` ใหม่ + เทสต์ regression (ข้อ 5-6) → deploy
2. `services/rm_history.py` + เทสต์หน่วย (ข้อ 1-4)
3. `services/rm_history_import.py` + เทสต์ import (ข้อ 7-9)
4. `tools/import_rm_history.py` + `--dry-run` กับชีทจริง → **โอดูรายงาน issues ก่อน**
5. `--apply` ทีละไฟล์ + ตรวจทานยอดต่อคัน (ข้อ 10) → ผ่านหมดค่อยไฟล์ถัดไป
