# รหัสกู้ฉุกเฉิน (Recovery Codes) — กู้บัญชี admin ที่ลืมรหัสได้เองไม่ต้องพึ่ง AI

**วันที่:** 2026-07-02 · **สถานะ:** รอโออนุมัติ (ยังไม่เขียนโค้ด)

## ปัญหา

- ระบบมี admin รีเซตรหัสให้คนอื่นได้อยู่แล้ว แต่ถ้า **admin (yk1) ลืมรหัสเอง** ไม่มีทางกู้บนเว็บ — ต้อง SSH เข้าเซิร์ฟเวอร์แก้ DB (เกิดจริง 2 ก.ค. 2026 หลัง DB swap ทับรหัส)
- กฎใหม่ของโอ: ทุกอย่างต้องเป็นหน้า/ปุ่มใน MVP ที่โอกดเองได้ ไม่ผูกกับ AI

## ทางเลือกที่พิจารณา

| ทาง | ข้อดี | ข้อเสีย | ตัดสิน |
|-----|-------|---------|--------|
| **A. รหัสกู้ฉุกเฉินใช้ครั้งเดียว 5 ชุด** | ไม่พึ่งอีเมล/บริการนอก, โค้ดน้อย, ใช้ได้แม้เน็ต/อีเมลล่ม | ต้องเก็บกระดาษ/โน้ตให้ดี | ✅ เลือก |
| B. ลิงก์รีเซตทางอีเมล | UX คุ้นเคย | ต้องตั้ง SMTP/Gmail ส่งเมล = ชิ้นส่วนเพิ่ม + ถ้าอีเมลเข้าไม่ได้ก็จบเหมือนเดิม | ❌ |
| C. สคริปต์บนเซิร์ฟเวอร์ + คู่มือ | ง่ายสุด | ขัดกฎ no-AI (โอกดเองบนเว็บไม่ได้) | เก็บเป็น**แผนสำรอง** มี runbook |

## ดีไซน์ (ทาง A)

### 1. ตารางใหม่ `RecoveryCode`

`id, user_id (FK appuser), code_hash (bcrypt), used_at (nullable), created_at`

- Migration: `SCHEMA_VERSION` 18 → 19, `CREATE TABLE` ใน `lifespan()` ตามแพทเทิร์นเดิม (additive, ไม่แตะตารางเงิน)
- เก็บเป็น bcrypt hash เหมือนรหัสผ่าน — เปิด DB ก็อ่านรหัสจริงไม่ได้

### 2. หน้าออกรหัส `/account/recovery-codes` (admin เท่านั้น, ออกให้บัญชีตัวเอง)

- ปุ่ม "สร้างรหัสกู้ชุดใหม่ (5 รหัส)" → โชว์รหัสจริง **ครั้งเดียว** + ปุ่มพิมพ์ → โอพิมพ์/จดเก็บ
- สร้างชุดใหม่ = ยกเลิกรหัสเก่าที่ยังไม่ใช้ทั้งหมด
- รูปแบบรหัส: 3 กลุ่ม `XXXX-XXXX-XXXX` (ตัวพิมพ์เล็ก+ตัวเลข, สุ่มด้วย `secrets`)
- หน้านี้โชว์สถานะ: เหลือกี่รหัส / ใช้ไปเมื่อไหร่

### 3. หน้ากู้ `/login/recover` (สาธารณะ — ลิงก์ "ลืมรหัสผ่าน?" ใต้ฟอร์ม login)

- ฟอร์ม: username + รหัสกู้ → ถูกต้อง = mark `used_at`, ตั้ง `must_change_pw=1`, ล็อกอินให้ แล้วเด้งไป `/account/password` **บังคับตั้งรหัสใหม่ทันที**
- ใส่ผิด = นับผ่าน `login_guard` เดิม (ล็อกชื่อ 15 นาที / ล็อก IP) — กันเดารหัสกู้แบบเดียวกับเดารหัสผ่าน
- route อยู่ใต้ `/login` ซึ่งเป็น PUBLIC_PREFIXES อยู่แล้ว ไม่ต้องแก้ RBAC

### 4. แผนสำรอง (runbook)

- เขียน `docs/MVP_ADMIN_RECOVERY_RUNBOOK.md`: ขั้นตอน SSH/AnyDesk รีเซตรหัสตรงใน DB (ตามที่ทำ 2 ก.ค.) — เผื่อกระดาษหาย + ทำตามกฎ "script ต้องมี runbook"

### 5. เกี่ยวพันกับ DB swap gotcha

- ตาราง `recoverycode` อยู่ใน `app.db` เดียวกัน → ขั้นตอน preserve ตอน swap DB ต้องคลุมทั้ง `appuser` **และ** `recoverycode` (ไม่งั้นรหัสกู้บนเซิร์ฟเวอร์หายทุก deploy เหมือนรหัสผ่าน)

## สิ่งที่ไม่ทำ (YAGNI)

- ไม่ทำ email reset, ไม่ทำ OTP/2FA, ไม่ทำ recovery codes ให้ role อื่น (คนอื่นให้ admin รีเซตตามเดิม), ไม่ทำหมดอายุรหัสกู้

## การทดสอบ (TDD)

1. สร้างรหัส 5 ชุด → เหลือ 5, สร้างใหม่ → ชุดเก่า invalid
2. กู้สำเร็จ → ใช้ซ้ำรหัสเดิม = ปฏิเสธ, บังคับเปลี่ยนรหัสก่อนใช้หน้าอื่น
3. กู้ด้วยรหัสผิด 5 ครั้ง → ชื่อโดนล็อก 15 นาที
4. user ที่ไม่ใช่ admin เข้า `/account/recovery-codes` ไม่ได้
5. ไม่แตะเงิน — `net_guard` ไม่ขยับ (ฟีเจอร์ auth ล้วน)
