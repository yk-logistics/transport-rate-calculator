## §0 กติกากลาง — บังคับทุกงาน (อ่านก่อนเริ่มทุกครั้ง)

1. **เริ่มงาน**: `git checkout -b feat/<ชื่องาน>` จาก main (ห้ามทำบน main); อ่าน CLAUDE.md + memory ที่เกี่ยว
2. **TDD**: เขียนเทสต์ก่อน (pattern มีให้ลอกใน `app/tests/` — fixture มาตรฐาน: temp sqlite + `appmod.init_db()` + login yk1/changeme1 + `YK_INSECURE_COOKIES=1`; ดูตัวอย่างครบใน `tests/test_kb_payout_page.py`)
3. **เงิน = โมเดลใหญ่เท่านั้น** — "ใหญ่" หมายถึง **Fable หรือ Opus** (⚠️ โอใช้ Fable ได้ถึง 7/7/2026 — หลังจากนั้น Opus เป็นตัวใหญ่สุด): preflight ก่อน, `tools/net_guard.py before/after --allow <run>`, ห้ามเดา, DB server = ความจริง (**ห้าม push local DB**); **งานเงินทุกงานเมื่อทำเสร็จต้องทิ้ง runbook วิธีทำ+วิธีตรวจแบบจับมือ** (ตัวอย่างดี: KB_PAYOUT_RUNBOOK, PREFLIGHT_CY_KB) ให้ Opus รอบหน้าทำเคสคล้ายกันได้โดยไม่ต้องคิดใหม่ — ความรู้อยู่ในไฟล์ ไม่ใช่ในหัวโมเดล
4. **Deploy**: probe ก่อนทับ (ดึงไฟล์ server เทียบ HEAD~1 ต้องตรง) → scp เฉพาะไฟล์ที่แก้ → restart แบบ kill-by-8010-PID (สคริปต์ตัวอย่างในไฟล์นี้ §0.1) → verify: marker ในไฟล์ server + logic probe ด้วย `.venv` ของ server + public 200 + พอร์ต 8020 (LINE) ยังรอด
5. **ปิดงาน**: เทสต์ทั้ง module ที่เกี่ยวผ่าน → commit (เฉพาะไฟล์ตัวเอง — ระวังไฟล์ session อื่นค้าง ดู `git status` ก่อน add) → deploy+verify → อัปเดต % ในแพลน + memory + runbook (กฎ handoff: เขียนให้เด็กกว่าทำต่อได้)
6. **schema ใหม่**: เพิ่ม model ใน `models.py` + import ใน `main.py` + bump `SCHEMA_VERSION` (ตารางใหม่ = create_all พอ ไม่ต้อง ALTER) — ดูตัวอย่าง KbSettle (v32)
7. **สิทธิ์hน้าใหม่**: เพิ่ม prefix ใน `app/permissions.py` MENUS+MATRIX + ลิงก์เมนูใน `templates/base.html` gate ด้วย `can_see(request, "<path>")` — หน้าเงิน/ลับ = admin เท่านั้น, การเงินทั่วไป = finance matrix
8. **Google Drive/Sheet**: อ่านผ่าน service account (key `noble-history-...json` — dev: ราก repo, server: โฟลเดอร์ app); **แก้ Sheet ต้องถามโอก่อน + ใส่ cell note ทุกช่อง** (กฎเหล็ก); ของแชร์แบบลิงก์ต้องเปิดจากรหัสโฟลเดอร์ (ค้นชื่อไม่เจอ)
9. **วันเวลา**: `| dmy` filter ใน template เสมอ; พูดถึงเวลา = ดูนาฬิกาจริง
10. **ภาษาไทยผ่าน ssh/console เพี้ยน** — verify ด้วย ASCII marker หรือเขียนไฟล์ UTF-8 แล้ว scp กลับ
11. **กฎห้ามออกนอกแบบ (โอ 3ก.ค. — เทียบงานก่อสร้าง: สเปคนี้คือแบบสถาปนิก+วิศวกร ผู้ทำคือช่างเท):**
    ก่อนแตะโค้ด ผู้ทำต้องเขียน "แผนเท" สั้นๆ (ไฟล์ที่จะแก้ + ลำดับ) เทียบกับสเปคข้อต่อข้อ —
    **ตรงสเปค = ทำเลยไม่ต้องถาม; อยากทำต่างจากสเปคแม้นิดเดียว (ชื่อตาราง สูตร โครงหน้า) = หยุด
    แล้วรายงานว่าติดอะไร เสนอทางเลือก รอคนสั่ง — ห้ามตัดสินใจแทน**; ถ้าสเปคเงียบเรื่องไหน
    (สี ขนาดปุ่ม wording) ให้ทำตาม pattern หน้าที่มีอยู่ใกล้เคียงสุด แล้วจดไว้ในรายงานปิดงาน

**การทำงาน:** (1) การ์ด G1 โชว์ "รูปเก่าสุด <วัน> · ครบกำหนดย้าย <วัน>" + เตือนเมื่อถึงกำหนด/ดิสก์ตึง (2) โอเสียบ External ที่ **เครื่อง server** → เปิดหน้า /admin/server-health → ระบบตรวจเจอไดรฟ์ใหม่ (มี marker file YK_ARCHIVE.txt ที่สร้างให้ครั้งแรก) → ปุ่ม "ย้ายรูปเก่าลงแผ่นนี้" (3) ขั้นตอนย้ายต่อไฟล์: copy → ตรวจ hash ตรง → ค่อยลบต้นทาง → จดตำแหน่งใหม่ลงตาราง `MediaArchive` (ฝั่ง app.db: line_message_id, archive_disk, path) — **ห้ามเขียน line_archive.db** (4) หน้า /line: รูปที่ถูกย้าย โชว์ข้อความ+ป้าย "รูปอยู่แผ่น EXT-01" (ถ้าแผ่นเสียบอยู่ = เปิดได้เลย) (5) ปิดท้ายพิมพ์สรุป: ย้ายกี่ไฟล์ กี่ GB เหลือพื้นที่เท่าไหร่
**เกณฑ์ผ่าน:** ย้ายชุดทดสอบ 100 ไฟล์: hash ตรงทุกไฟล์ก่อนลบ, ค้นเจอ+ป้ายถูก, ดึงแผ่นออกระบบไม่พัง (โชว์ป้ายเฉยๆ)
