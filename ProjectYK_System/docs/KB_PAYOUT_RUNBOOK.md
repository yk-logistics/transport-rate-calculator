# Runbook: คำนวณ KB จ่ายคืนเจ้าของงาน (CY)

> คู่มือส่งต่องาน — เขียนไว้ให้ **ใครก็ได้ทำแทนกันได้** ทั้งคนจริงและ AI โมเดลเล็ก (Haiku/Sonnet/Qwen)
> ไม่ต้องรู้บริบทอื่นของระบบเลย ทำตามนี้พอ (โอสั่ง 2 ก.ค. 2569: ทุกงานต้องมีคู่มือให้โมเดลรุ่นถัดไปทำต่อได้)

## ทางที่ 1 — หน้าเว็บ (โอใช้เอง ไม่ต้องมี AI)

1. เข้า **https://app.yklogistics.uk/kb-payout** (ล็อกอิน admin เท่านั้น — role อื่นมองไม่เห็น)
2. ดูสลิปโอนจากลูกค้า → พิมพ์ **จำนวนเงิน** ลงช่อง (เช่น `19027.98`) → กด "จับคู่อินวอย"
3. ระบบบอก: ใบไหนบ้าง + KB รวม + **ยอดโอนคืนเจ้าของงาน 90%** + ใบหัก ณ ที่จ่าย 3%
4. ถ้าไม่กรอกยอด = เห็นตารางอินวอย CY ทุกใบพร้อม KB ต่อใบ

## ทางที่ 2 — คำสั่งในเครื่อง (สำหรับ AI ทำแทน)

รันจากรากโปรเจกต์ (`Project YK`) ด้วย python ของ app venv:

```powershell
# ดูอินวอยทุกใบ + KB
ProjectYK_System\app\.venv\Scripts\python.exe ProjectYK_System\tools\kb_payout.py list

# ลูกค้าโอนมา X บาท → เป็นใบไหนบ้าง + KB (ใส่ยอดตรงจากสลิปธนาคาร)
ProjectYK_System\app\.venv\Scripts\python.exe ProjectYK_System\tools\kb_payout.py match 19027.98
```

ถ้าคอนโซลพังเพราะภาษาไทย ให้ตั้ง `PYTHONIOENCODING=utf-8` ก่อน หรือ pipe ลงไฟล์

## กติกาธุรกิจ (อย่าเดาใหม่ — โอยืนยันแล้ว 1 ก.ค. 2569)

- **KB ต่อใบ = ค่าขนส่งในบิล − (ราคาเสนอ × จำนวนตู้) − OT**
  - ค่าขนส่ง: ชีท "ค่าขนส่ง" ในไฟล์อินวอย คอลัมน์ J ต่อตู้ (ปกติ 5,000) — **ห้ามใช้ยอดหน้าปะหน้า** (มันรวมค่าสำรองจ่าย)
  - ราคาเสนอ: เลขใน**ชื่อไฟล์**ก่อนเครื่องหมาย + (เช่น `CYIV2606-005 JUN TAI 4600+100` → 4,600)
  - OT: เลข**หลัง** + ในชื่อไฟล์ หักครั้งเดียวทั้งใบ (ไม่ใช่ต่อตู้) ไม่มี + = 0
- **โอนคืนเจ้าของงาน = KB × 90%** (บริษัทเก็บ 10%) → CY = ชาญณรงค์ มาลีแย้ม กสิกร 844-205-5344
- **ใบหัก ณ ที่จ่าย = 3% ของ KB เต็ม** — ออกเอกสารอย่างเดียว **ไม่ลบจากยอดโอน**
- การจับคู่ยอดโอน: CY มักหักภาษี ณ ที่จ่าย **1% เฉพาะส่วนค่าขนส่ง** (ไม่หักส่วนสำรองจ่าย)
  — ตัวโปรแกรมลองทุกแบบให้อัตโนมัติ (เต็ม / −1% ขนส่ง / −1% ทั้งใบ / −3%)
- ตัวอย่างจริง: โอน 1 ก.ค. 69 `19,027.98` = CYIV2606-023 (13,214.98) + CYIV2606-026 (5,963)
  → KB 1,713 → โอนคืน 1,541.70 → ใบ ณ ที่จ่าย 51.39

## ข้อควรรู้ / ปัญหาที่เจอบ่อย

- ข้อมูลมาจาก Google Drive โฟลเดอร์ **"ใบวางบิล LCB" → C.Y** (แยกโฟลเดอร์ตามเดือน เช่น 6.2026)
  — ใบใหม่โผล่เองเมื่อฝ่ายบิลลิ่งเอาไฟล์ลง Drive ไม่ต้อง import อะไร
- ต้องมีไฟล์ key ของ service account (`noble-history-...json`) อยู่ที่รากโปรเจกต์ (dev) หรือโฟลเดอร์แอป (server)
- ไฟล์อินวอยถูก cache ไว้ (`_kb_payout_cache`) — ถ้าไฟล์ใน Drive ถูก **แก้ทับใบเดิม** ให้ลบโฟลเดอร์ cache แล้วรันใหม่
- จับคู่ไม่เจอ = อาจเป็นใบเดือนที่ยังไม่มีใน Drive / ลูกค้าโอนหลายก้อนรวม / มีส่วนลด → ถามโอ อย่าเดา
- **read-only ทั้งหมด** — เครื่องมือนี้ไม่แตะเงินเดือน ไม่แตะฐานข้อมูล แค่คำนวณให้ดู
- ยังไม่รองรับ NHL/MOL/Siam i (สูตรนับตู้ × 110/100/50) — งานต่อไป
