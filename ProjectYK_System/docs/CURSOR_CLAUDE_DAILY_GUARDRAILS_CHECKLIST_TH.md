# Cursor + Claude Code: Daily Guardrails Checklist (Project YK)

เช็กลิสต์สั้นสำหรับโอ (1 คน) ก่อนเริ่มงานแต่ละวัน เพื่อกันงานหลุด/ข้อมูลเงินตกหล่น

## 1) เปิดงาน 5 นาทีแรก (ต้องทำทุกวัน)

- [ ] ยืนยัน scope วันนี้เป็นงานเดียวชัดเจน (เช่น "แก้ import petty", "แก้ payroll BIGC เดือนนี้")
- [ ] ยืนยันระดับความเสี่ยงงาน:
  - `low`: UI/ข้อความ/route เล็ก
  - `high`: กระทบเงิน/import/payroll/recompute
- [ ] ถ้าเป็น `high` ให้ล็อกว่าจะใช้โหมดรอบคอบ (ไม่ใช้ ultra-lean)
- [ ] เปิดไฟล์อ้างอิงบังคับ: `ProjectYK_System/AGENT_BOOTSTRAP.md`, `ProjectYK_System/MODULE_REGISTRY.md`

## 2) Guardrails ก่อนลงมือแก้โค้ด

### 2.1 ความชัดเจนของโจทย์
- [ ] ถ้าโจทย์กำกวม (ชื่อคน/ไซต์/รอบเดือน) ให้ถามยืนยันก่อนเสมอ
- [ ] จำกัดคำถามยืนยันไม่เกิน 3 ข้อ

### 2.2 งานที่กระทบเงิน (บังคับ preflight)
- [ ] ตรวจ `unlinked records` (มีรายการหักที่ยังไม่ผูกคนขับหรือไม่)
- [ ] ตรวจ `cycle tag` (เดือนวิ่ง vs เดือนจ่าย ถูกต้อง)
- [ ] ตรวจ `cross-site name collision` (ชื่อซ้ำข้ามไซต์)
- [ ] ตรวจ `source mismatch` (daily/fuel/petty/payroll ขัดกันไหม)

### 2.3 ห้ามทำลายของเดิม
- [ ] หลีกเลี่ยงคำสั่งลบ/รีเซ็ตแบบทำลายข้อมูล
- [ ] ถ้าต้องแก้ข้อมูลจำนวนมาก ให้มีทางย้อนกลับ (backup/script ที่รันซ้ำได้)

## 3) Guardrails หลังแก้เสร็จ (ก่อนสรุป)

- [ ] รัน verify ที่เกี่ยวข้องจริงกับงาน
- [ ] ถ้าแก้ logic เงิน: ทำ recompute และเทียบ before/after
- [ ] ถ้าพบรายการตกหล่น ให้รายงานเป็นตัวเลข:
  - จำนวนรายการ
  - ยอดเงินที่ยังไม่ถูกคิด
  - จุดที่ต้องไปแก้ทันที (หน้า/คำสั่ง)
- [ ] สรุปผลในรูปแบบ 4 หัวข้อ:
  1) สิ่งที่ทำแล้ว
  2) สิ่งที่ค้าง/เสี่ยง
  3) คำถามยืนยันที่จำเป็น
  4) ขั้นตอนถัดไปที่แนะนำ

## 4) Safe Default รายวัน (ถ้าเลือกไม่ถูก)

- งานเล็กไม่กระทบเงิน -> ใช้ `ProjectYK_System/tools/CC_ULTRA_LEAN_5LINES.txt`
- งานกลาง/เริ่มถามกลับหลายรอบ -> ใช้ `ProjectYK_System/tools/CC_LEAN_START.txt`
- งานเงิน/import/payroll -> ใช้โหมดรอบคอบเต็ม + preflight 4 checks ทุกครั้ง
