เข้าใจครับ และผมเริ่มวางโมดูลให้แล้วจากไฟล์จริงของคุณ (ไม่ใช่แค่คิดลอยๆ)

สิ่งที่ผมทำให้ตอนนี้:

- สร้างเอกสารดีไซน์รอบแรกไว้ที่ `TransportRateCalculator/DAILY_MODULE_DESIGN.md`
- สร้างโครงโค้ดโมดูลใหม่ที่ `Salary/daily_module/`:

- ตรวจ syntax/lint แล้วผ่าน

## คำตอบสั้นก่อน
- เริ่มจากไฟล์เดิมก่อน: `AYU/BigC/LCB` คือความจริงของธุรกิจวันนี้
- ออกแบบระบบกลางให้รองรับ “หลายรูปแบบไฟล์” ผ่านตัวแปลแต่ละไซต์
- พอระบบนิ่งแล้วค่อยเปิดโหมด “คีย์ใหม่ในระบบ” ให้พนักงานใช้
- เป้าหมายปลายทาง: โปรแกรมเดียวจบ ตั้งแต่ Daily -> วางบิล -> เงินเดือน -> กระแสเงินสด -> Dashboard เจ้าของ

## ภาพรวมระบบที่ควรทำ (One Platform)

### 1) Data Intake Layer (รับข้อมูล)
- **โหมด A: Import ไฟล์เดิม** (สำคัญสุดช่วงแรก)
- **โหมด B: คีย์ใหม่ผ่านฟอร์ม** (เปิดทีหลัง)
- มี `Site Adapter` แยก `AYU`, `BigC`, `LCB` เพื่อ map คอลัมน์ต่างกัน
- มี `Validation Gate` ก่อนเข้าระบบจริง:
  - ชื่อไม่ตรง Master
  - ค่าเที่ยวว่าง
  - ตู้ซ้ำผิดเงื่อนไข
  - น้ำมันนอกรอบ
  - เอกสารตกหล่น

### 2) Core Engine Layer (สมองคำนวณ)
- **Work Engine**: รวม Daily เป็นงานมาตรฐาน
- **Billing Engine**: สร้างใบวางบิล/สรุปลูกหนี้อัตโนมัติ
- **Payroll Engine**: Trip/Mao, ภาษี, ประกันสังคม, เงินประกันตน, สดย่อย
- **Cost Engine**: ยึดสูตรจาก `COST_MODEL.md` (ต้นทุนจริง + ต้นทุนการเงิน)
- **Cashflow Engine**: รายรับ-รายจ่าย-เครดิตลูกค้า-ค้างจ่าย-ค้างรับ

### 3) Output Layer (ใช้งานจริง)
- มุมพนักงานคีย์: ใส่งาน/แก้ข้อมูล
- มุมแอดมิน: ปิดรอบ + ตรวจผิดปกติ + approve
- มุมบัญชี: วางบิล + เจ้าหนี้/ลูกหนี้
- มุม HR/เงินเดือน: จ่ายเงิน + สลิป + audit
- มุมเจ้าของ: Dashboard กำไรจริง, margin ต่อไซต์/ลูกค้า/รถ

## คำถามหลักที่คุณถาม: ใช้ไฟล์เดิม หรือ ให้คีย์ใหม่?
คำตอบ: **ทำแบบ Hybrid 2 เฟส**

- **เฟส 1 (เร็วและชัวร์):** ใช้ไฟล์เดิมเป็นหลัก 100%

- **เฟส 2 (นิ่งแล้วค่อยย้าย):** เปิดคีย์ใหม่ทีละทีม  
  ให้ระบบสร้างไฟล์/รายงานแทน Excel เดิมได้ ก่อนค่อยเลิกไฟล์เก่า

## Workflow รายเดือนแบบ “จบในโปรแกรมเดียว”
1. เลือกรอบ 16-15  
2. Import Daily/Fuel/สดย่อย ของทุกไซต์  
3. ระบบ map + แจ้ง error ให้แก้ในจอเดียว  
4. กด “Calculate รอบ”  
5. ได้พร้อมกัน:
   - สรุปต้นทุนงาน
   - ใบวางบิลลูกค้า
   - เงินเดือนพนักงาน
   - รายงานเงินสดเข้าออก
6. กด “Approve & Lock รอบ”  
7. Export เอกสาร/สรุปสำหรับเจ้าของทันที

## สิ่งที่ต้องมีเพื่อ “สมบูรณ์จริง”
- Rule-based validation (ไม่ให้ข้ามเงียบ)
- Interactive name matching + memory
- Audit trail ทุกตัวเลข (ย้อนที่มาได้)
- Versioning รอบเงินเดือน (แก้แล้วรู้ว่าใครแก้อะไร)
- Permission ตามบทบาท (พนักงาน/แอดมิน/เจ้าของ)
- เปรียบเทียบเดือนก่อนอัตโนมัติ (anomaly alerts)

ผมเสนอคุยและล็อกทีละส่วนในแชทนี้ต่อได้เลย:

ต่อมาก็จะเป็นเงินสดย่อย จะการมีโอนเงินให้ คนขับ หรือสำรองจ่ายก่อน วางบิลลูกค้าทีหลัง หรืออันไหนที่วางบิลไม่ได้ก็จะเข้าเป็นต้นทุน หรือ คนขับใช้แล้วเหลือเงินทอนแล้วไม่ทอน หรือมีเงินเบิก ก็ต้องเอาไปหัก ในเงินเดือน รวมถึง อุบัติเหตุ รายการที่คนขับขอผ่อนต่างๆ ก็จะ Pending อยู่ในสดย่อย คนคุมสดย่อย เวลาเงินออกเดิมก็จะมาลง Excel ทุก Transection รายจ่ายส่วนใหญ่เกือบทั้งหมดจะอยู่ในนี้

วางบิล ก็จะเป็นคนคีย์ เดลี่ ราคา รายละเอียดงานต่างๆ แล้วออกใบวางบิล แต่ละลูกค้าเอกสารก็จะคนละเงื่อนไข รูปแบบแตกต่างกัน ก็อาจจะต้องมาปรับ บอกคุณแต่ละลูกค้าอีกว่าเป็นยังไง รวมถึงการ สแกนเอกสาร แนบ หรือถ่ายรูป ก็จะค่อนข้างเสียเวลา

บัญชี ก็จะดู รายรับ รายจ่าย ตอนนี้เป็นคนที่ทำสดย่อยควบไปด้วย รวมถึงภาษี สรรพากร ยื่นแบบ สรุปรายรับ รายจ่ายให้เจ้าของ แจ้งเงินที่จะเข้าวันไหนๆ ให้เจ้าของวางบิลการเงิน

เงินเดือน ก็จะสรุป เดลี่ กับสดย่อย ออกมาเป็นแต่ละคน แต่ละไซท์

## สิ่งที่ต้องเพิ่มจากที่คุยไว้ (สำคัญมาก)
คุณเพิ่มบทบาทหลักครบแล้ว ผมสรุปเป็น 6 โมดูลปฏิบัติการ:

- `Dispatch/จัดรถ` (ต้นน้ำ): รับงานลูกค้า -> จัดรถ/คนขับ -> แจ้งงานไลน์
- `Daily Operations`: เก็บรายละเอียดงานวิ่งจริงหน้างาน
- `Petty Cash/สดย่อย`: โอนล่วงหน้า, เบิก, เงินทอน, pending หักเงินเดือน, ค่าเสียหาย/ผ่อน
- `Billing/วางบิล`: ออกใบวางบิลตามเงื่อนไขลูกค้า + แนบเอกสาร/รูป

- ไม่ต้องปวดหัว port forward / CGNAT
