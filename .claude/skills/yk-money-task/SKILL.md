# งานเงิน Project YK — กฎเหล็ก

> งานเงิน = payroll / billing / สลิป / ค่าเที่ยว / น้ำมัน / สดย่อย / deposit / แก้ DB ที่กระทบยอดใคร
> **โมเดลใหญ่ของเซสชันทำเองเท่านั้น — ห้าม delegate ให้ subagent/Sonnet/Haiku เด็ดขาด**
> ถ้าตัวหลักของเซสชันเป็น Sonnet: หยุด แจ้งโอให้สลับ `/model` เป็นตัวใหญ่ก่อน

## กฎเหล็ก (ผิดข้อเดียว = หยุดทำ)

1. **ห้ามเดา**: ไซท์ (BIGC/LCB/AYU), รอบเดือน (วิ่ง vs จ่าย), ชื่อคนขับคล้ายกัน, cross-site —
   กำกวมเมื่อไหร่ **หยุดถามโอ** (นี่คือข้อยกเว้นเดียวของกฎ "ทำงานต่อเนื่องไม่ต้องถาม")
2. **รอบที่ finalize แล้ว ห้าม recompute** — สดย่อยรายคนจะหายหมด
   แก้ยอดย้อนหลัง → แก้ item ตรงๆ หรือใช้กลไกค่าเที่ยวตกหล่น (`docs/PAY_ADJUSTMENT_RUNBOOK.md`)
3. **ก่อนแตะข้อมูล**: preflight ต้องบอกจำนวนแถวที่จะกระทบเป็นตัวเลข
   **ก่อน+หลังแก้**: `python ProjectYK_System/tools/net_guard.py before/after --allow <ids>` พิสูจน์ว่ารอบ/คนอื่นนิ่ง
4. **ยอดต้องกระทบยอดสองทางอิสระ** — ยอดจาก engine ต้องเท่ายอดที่ไล่มือจากต้นทางคนละเส้นทาง
   (สลิป vs payroll vs รูปโอนจริง) ตรงกันสองทาง = หลักฐาน; ทางเดียว = ยังเป็นสมมติฐาน
5. **ก่อน push DB ไป server**: รัน `probe_db.py` เทียบ local↔server ก่อนเสมอ —
   local เคย stale กว่า server แล้วเกือบทับของจริงมาแล้ว (ห้ามเชื่อว่า local ใหม่กว่า)
6. **ลบ test row ด้วย id ที่ระบบคืนมาตอนสร้างเท่านั้น** — ห้ามลบด้วย filter/เงื่อนไข
7. **ย้าย/แก้น้ำมัน = แก้ 2 ที่เสมอ** (รายการน้ำมัน + reconcile สลิป) — จบแล้วรัน `fuel_slip_reconcile.py` ยืนยัน
8. ตัวเลขสองแหล่งต่างกัน "นิดเดียว" ไม่มีในงานเงิน — หาสาเหตุจนเจอ ห้ามปัด

## เฟสหาข้อมูล (forensic) — ก่อนจะแก้อะไร ต้องชี้ตัวรายการให้ได้ก่อน

- **ข้อมูลจริงอยู่ไหน เชื่อได้แค่ไหน → `ProjectYK_System/docs/DATA_TOPOLOGY.md`** (server = ตัวจริง; mirror ตี 3 = เมื่อวาน; dev DB = เปล่า ห้ามใช้)
- เส้นแบ่ง "ค้นต่อ vs หยุดถามโอ": ค้นเองให้สุดทางที่**ข้อมูลอยู่ในมือ** (DB/mirror/ไฟล์/ชีท) — แต่ถ้าสิ่งที่ต้องใช้ตัดสิน**ไม่อยู่ในเครื่องและไม่มีทางหาได้เอง** (เช่น ต้องรู้ว่าโอหมายถึงใคร/รายการไหน/ราคาจริงเท่าไหร่) = หยุดถามทันที อย่าเดาแทน
- **คำตอบ "หาไม่เจอ/ไม่มี" เป็นคำตอบที่ถูกต้องได้** — ต้องมีหลักฐานประกอบ (เช่น diff snapshot นิ่ง) และห้ามคว้ารายการที่ "ดูน่าจะใช่" มาตอบเพื่อปิดงาน: ราคาแปลกๆ อาจเป็นเคสพิเศษที่ถูกแล้ว (KB, อนุโลม, งานยกเลิก, เก็บ %)
