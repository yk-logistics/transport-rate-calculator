Oatside (บ้านบึง→P&G) เก็บบิลจาก GPS แต่ daily คนคีย์ต่างกันเพราะ **คนคีย์แยกบรรทัด** ให้สิ่งที่ GPS มองไม่เห็น/ระบบยุบรวม:

- **Backhaul (BH) ขากลับ P&G→บ้านบึง** (Daily คอลัมน์ G="BH") + **ตีเปล่าไป P&G** (col H/I) = เก็บ **50% ของเรทวันนั้น** ต่อขา. GPS มองไม่เห็น → ต้องใส่มือใน `Oatside/oatside_config.json` คีย์ `manual_return_trips` `{dest_date,plate,amount_baht,note}`. PM/TO เลขใบงาน = ไม่ใช่ event.
- **ช่องแสดงผล ตีเปล่า vs ขากลับ (2026-06):** manual_return entry มี field `"kind"`: `"backhaul"` (default→ช่อง **ขากลับ**) หรือ `"deadhead"` (→ช่อง **ตีเปล่า/ส่วนเพิ่ม** + badge ตีเปล่า). เป็น **display-only ยอดรวมไม่ขยับ** (deadhead ยังอยู่ใน sum_manual_return → grand เท่าเดิม; แค่ย้าย cell + summary แยกบรรทัด R=ขากลับ / Rd=ตีเปล่า). โค้ด: `merge_manual_return_into_pday/_audit`, `trip_row_pricing_cells(deadhead_baht=)`, `sum_manual_deadhead/backhaul_baht`. ตรวจ: ทุก (plate,day) total ไม่เปลี่ยน (grand รอบ พ.ค. = **1,496,160** หลังแก้ window-filter ด้านล่าง; ก่อนแก้คือ 1,499,410).
- **แตก "เที่ยวว่าง GPS นับเต็ม" (2026-06):** บางวันรถวิ่งว่าง(ตีเปล่า)ไป P&G แต่ GPS เห็นเป็นเที่ยวเต็ม → over-bill base, under-bill BH (net 0). อยากแตกให้เห็น ใช้ config `remove_matched_trips:[{plate,dest_date,count}]` ตัดเที่ยว matched ท้ายสุดออกจาก base (`apply_remove_matched_trips` ใน main หลัง build_trips) **ต้องคู่กับ `exclude_50` ใน oatside_billing_overrides.json** (กัน +50% ลั่นตอนเหลือ 1 เที่ยว) + manual ตีเปล่า50%+ขากลับ50%. ผลรวมเท่าเดิม (base −rate = ตีเปล่า+ขากลับ). ตัวอย่าง: 71-8005 20/05 → 1เต็ม7,456+ตีเปล่า3,728+ขากลับ3,728=14,912. เที่ยวที่ตัดไม่โผล่ unmatched. CPD ลด 1.
- **ตัดเที่ยวผี (รถไม่ได้วิ่งจริง, 2026-06):** ใช้ `remove_matched_trips` เหมือนกัน แต่ **ไม่ใส่ manual ชดเชย** → ยอดรวมลดจริง. ต้องคู่ `exclude_50` เสมอ: ถ้าวันนั้นเหลือ 0 เที่ยวแต่ GPS ยังเห็นรถที่โรงงาน branch n==0 จะเก็บ **no_finish 100%** แทน (ยอดไม่ลด!) — exclude_50 บล็อกทั้ง branch n==1 และ n==0. ตัวอย่าง: 71-8009 28/05 ABNORMAL → grand 1,496,160→1,485,120 (−11,040 = base 7,360 + one-trip 50% 3,680 ที่เคยเก็บวันนั้น). Deploy: rebuild → refresh mirror `reports/oatside-pg-2026` (เก็บ 4 ไฟล์ manual-check) → commit repo หลัก → `deploy_oatside_report.ps1 -Push`.
- **ค่าเสียเวลา**: คนคีย์เพิ่มบรรทัดใหม่; ระบบลงเป็น surcharge บรรทัดเดียว (`surcharge_billed_day`: 1 เที่ยวจบ=50% one_trip, 0 เที่ยวจบ+โรงงาน active=100% no_finish). กฎโอ: ถ้า **system surcharge รวมทั้งคัน ≥ keyer demurrage รวม = OK** ไม่ต้องเพิ่ม (ปกติระบบเก็บมากกว่าเพราะใส่ 50% ทุกวัน 1 เที่ยว).
- **no_finish 100% ใช้เรท "วันที่รอ" ไม่ใช่วันเที่ยวจบ** → เลขอาจ ≠ ค่าขนส่งของเที่ยว match เพราะดีเซลคนละวัน (โอยืนยัน 2026-06 ให้คงไว้แบบนี้ = ถูกแล้ว ไม่ใช่ bug).
- **เลือกเดือน/รอบ = `report_start_date`+`report_end_date` ใน `oatside_config.json`** (กรองตาม trip_date/dest_date; null=ไม่กรอง). พ.ค.2026 = 2026-05-01..2026-05-31. แก้ 2 บรรทัดนี้แล้ว rebuild = เปลี่ยนรอบ. **(2026-06 fix)** เดิม window กรองเฉพาะ trips/surcharge ผ่าน `_date_in_report_window` แต่ **ไม่กรอง `manual_return_trips`/`manual_extra_trips`** → manual ขากลับนอกรอบ (เช่น 22/04 รถ72-1217 = 3,250 carry-over) หลุดเข้า grand ทั้งที่ไม่มีแถวเที่ยว ทำให้ Excel รายเที่ยว (sum คอลัมน์) ≠ หน้าสรุป. แก้: filter manual ตาม window ใน `load_oatside_config` ก่อน return (ดู `_mt_in_window`). ผล: grand 1,499,410→1,496,160, ตรงกับ Excel. รายการยังอยู่ใน config (ไม่ลบ) — เปลี่ยน window กลับมาคิดได้.
- **คอลัมน์ "เลขที่ใบงาน" (2026-06)** แทรกก่อน ค่าขนส่ง ในตารางเที่ยว. เลขใบงานอยู่ใน **Daily คนคีย์ คอลัมน์ I "เลขที่"** (ไม่ใช่ GPS) → `Oatside/extract_job_numbers.py` ดึงเฉพาะลูกค้า Oatside + เลขจริง (ทิ้งข้อความไทยเช่น "ไม่มีใบงาน ทำไม่ทัน") ลง `Oatside/oatside_job_numbers.json` {"PLATE|YYYY-MM-DD":[jobs]}; builder `load_job_numbers()` แมปเข้า (plate,trip_date) แสดง **แถวแรกของวัน** (แบบ1, แถวถัดไปเว้นว่าง, UM=—). Daily ไม่ตรง GPS 1:1 จึงไม่จับทีละเที่ยว. **รอบใหม่:** รัน `python Oatside/extract_job_numbers.py "<dailyxlsx>" "<sheet>"` (default sheet "May 26") refresh JSON แล้ว rebuild. 71-6802/72-1217/72-1218 ไม่มีใบงาน Oatside ในไฟล์โฮมโปร→เว้นว่าง. **บั๊กที่แก้:** Excel export เคยบวกเลขใบงานที่เป็นตัวเลขล้วน (เช่น 20100050) → เปลี่ยนเป็นตัดสิน numeric **ทั้งคอลัมน์** (มีตัวอักษรปน=text ไม่บวก).
- **trips.html มีปุ่ม export (Print/PDF · Excel-as-shown .xls · PNG)** ฝั่ง client อ่านจากตารางที่เห็น (กรอง+ซ่อนคอลัมน์ติดไป); Excel = ตัวเลขจริง summable + แถว "รวม"; โค้ด `_TABLE_EXPORT_JS` + ปุ่มในเทมเพลต trips ของ `build_oatside_reports.py`; PNG ใช้ `Oatside/assets/html2canvas.min.js` (build copy เข้า report_dir). แทรกเข้า HTML ที่ build แล้วโดยไม่ rebuild: `python ProjectYK_System/tools/patch_oatside_trips_export_buttons.py` (idempotent/re-appliable).

- **เช็คไขว้ไฟล์ใบงานลูกค้า (2026-06):** ลูกค้าส่ง `Downloads/Oatside May 2026.xlsx` Sheet1 (B=Shipment Date, C=TO-OTLxxxxx, I=ทะเบียน). สคริปต์ `Oatside/_match_customer_jobs_may.py` จับคู่ใบงาน↔เที่ยว GPS (ทะเบียน+วันใกล้ Origin_Out, 4 pass) → `Oatside/customer_job_match_may2026.csv`. ผล พ.ค.69: 140/152 เที่ยวมีใบงานลูกค้า, 9 เที่ยวมี TO จากเดลี่ (ลูกค้าตกหล่น โดยเฉพาะ 71-5042 ที่ไฟล์ลูกค้ามีแค่ 1/8), เหลือ 3 เที่ยว GPS-only (72-1218 06+07/05, 71-8005 21/05). ฝั่งกลับกัน: ลูกค้ามีใบงาน 71-8002 ช่วง 05-07/05 รวม 3 ใบ แต่ GPS เราไม่มีเที่ยว 71-8002 ก่อน 10/05 เลย = อาจ**คิดขาด** (ยังไม่เก็บเพิ่ม รอโอตัดสิน). **คอลัมน์ "เลขใบงาน (ลูกค้า)"** อยู่ใน builder แล้ว (แยกจากคอลัมน์เดลี่ ซึ่ง rename เป็น "เลขที่ใบงาน (เดลี่)"): สคริปต์ match เขียน `oatside_customer_jobs.json` **v2 key รายเที่ยว `PLATE|Origin_In`** → builder `load_customer_jobs_by_trip()` แสดง**ช่องละเลขรายแถว**; คอลัมน์เดลี่ (รายวัน) กระจายตามลำดับ Origin_In ของเที่ยวในวัน, เลขเกินจำนวนเที่ยวซ้อน `<br>` ในช่องเที่ยวสุดท้าย (ดู `daily_job_html`/`cust_job_html` ใน write_html). **ไฮไลท์ตรวจสอบ (display-only):** ช่องลูกค้าว่างบนเที่ยว matched = td.cust-missing แดง "ไม่มีใบงาน" (`_cust_cell`); เลขเดลี่รายตัวเช็คกับ `all_docs` ใน JSON v3 (`load_customer_doc_index`/`_daily_num_html`) → เหลือง job-nocust = ไม่มีในไฟล์ลูกค้า, แดง job-conflict = ลูกค้าลงคนละทะเบียน (tooltip บอกคัน+วัน). ลูกค้าประกาศ: เที่ยวไม่มีใบงาน = ไม่จ่าย. รอบเดือนใหม่: ขอไฟล์ลูกค้า → อัปเดต path ในสคริปต์ → รัน → rebuild.
