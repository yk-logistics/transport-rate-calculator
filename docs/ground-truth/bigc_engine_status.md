# BIGC/AYU engine คำนวณเอง — ข้อสรุปสุดท้าย (โอ-confirmed 2026-06-28)

## สรุป: BIGC/AYU ใช้ "ลอกยอด" ถาวร — ไม่ให้ engine คำนวณเอง

โอยืนยัน 2026-06-28 ว่าตัวเลขหลักของ BIGC เป็น **ดุลพินิจรายเดือน ไม่มีสูตร**:
- **เงินเดือน (คอลัมน์ E ในชีท รวม YK)** = โอ**กรอกเองต่อคนต่อเดือน** (เช่น เสกสรร x/10=2/10 แต่ E=9,000 เต็ม ไม่หารตาม ratio). engine คิดเองไม่ได้.
- **ค่าเที่ยว (C) + เรทน้ำมัน (F)** = โอยึดตาม Excel แต่ละเดือน.
- x/10 (คอลัมน์ J) = อัตราส่วนอ้างอิง ไม่ใช่ตัวหาร base.

→ ในเมื่อ base/เที่ยว/น้ำมัน ทั้งหมดคำนวณใน Excel เสร็จแล้ว = **ลอก net (คอลัมน์ O) ตรงๆ คือวิธีที่ถูกต้องและแม่นที่สุด** ไม่ใช่ข้อจำกัด. engine `bigc_monthly` ที่มีอยู่ (คิด base=9000−หักวันลา) จะ**ผิด**ถ้าใช้ เพราะโอไม่ได้คิดแบบนั้น.

## ชีท รวม YK — โครงคอลัมน์ (อ้างอิง)
| col | หัว | คือ |
|-----|-----|-----|
| B | ชื่อพขร. | คนขับ |
| C | ค่าเที่ยว | ค่าเที่ยวรวมเดือน |
| E | เงินเดือน | base (โอกรอกเอง) |
| F | ค่าเรทน้ำมัน | rebate ± |
| G | รวม | gross = C+E+F |
| I | เงินประกันตน | +/- (บริษัทให้/คืน) — **ทุกคนทุกไซท์มี** |
| J | x/10 | อัตราส่วน (อ้างอิง) |
| K | ประกันสังคม | หัก ปกส |
| M | ยอดเบิกหักสิ้นเดือน | เบิกหัก |
| O | จ่าย | **net (ลอกตัวนี้)** |

## เงินประกันตน (คอลัมน์ I)
โอ-confirmed: **net ที่ลอก (O) รวมเงินประกันตนไปแล้ว ถูกต้อง — ไม่ต้องแยก field** (ตรวจแล้ว เสกสรร/บุญชอบ/พรศักดิ์/มานพ net ตรง Excel เป๊ะ).

## วิธีทำรอบใหม่ BIGC/AYU (ทุกเดือน)
1. โอคำนวณใน Excel (รวม YK / แบงค์) เหมือนเดิม.
2. สกัด net ต่อคน → CSV → รัน onboard script (idempotent, wipe+recreate per-site):
   - BIGC: `tools/onboard_bigc_from_ruamyk.py` (อ่าน docs/ground-truth/bigc_ruamyk.csv)
   - AYU: `tools/onboard_ayu_from_paid.py` (อ่าน ayu_paid.csv)
3. payrun ติด [COPY-LOCK] กัน recompute. โอ review + finalize.
