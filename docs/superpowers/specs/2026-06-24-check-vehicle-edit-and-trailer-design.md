# Design — "ตรวจสภาพรถ": ช่างแก้ประเภทรถ/เพิ่มหาง + ตรวจหางต่อจากหัว

วันที่: 2026-06-24
โมดูล: `ProjectYK_System/app/` — flow magic-link ตรวจสภาพ (`/check/*`)
สถานะฐาน: ฟีเจอร์ตรวจยางทำเสร็จ + deploy แล้ว; เพิ่งเพิ่ม TRL8 + ป้ายไทย (commit `d64d4ab`)

## ที่มา (โอสั่ง)
- ในลิงก์ที่คนขับ/ช่างเปิด ให้แก้ "ประเภทรถ" (6/10 ล้อ) ได้เอง และเพิ่ม/เลือกทะเบียนหางได้
- หางกับหัว = **คนละคัน จับคู่ตอนตรวจ** (หางไม่ได้ใช้คันเดิมตลอด)
- คนแก้ข้อมูลรถ = **ช่างเท่านั้น** (คนขับเห็นผิดแจ้งช่าง)
- หน้านี้เรียกว่า **"ตรวจสภาพรถ"**

## ขอบเขต (4 ส่วน)

### 1. เปลี่ยนชื่อหน้า → "ตรวจสภาพรถ"
- `check_driver.html`, `check_mechanic.html`, `check_landing.html`: `<title>` + หัวข้อ h1 จาก "ตรวจยาง"/"ช่าง — ตรวจ/วัดยาง" → "ตรวจสภาพรถ"
- ข้อความล้วน ไม่กระทบ route/logic

### 2. ช่างแก้ "ประเภทรถ" — เฉพาะลิงก์ช่าง
- `check_mechanic.html`: เพิ่มกล่อง `<details>` พับ "🔧 แก้ข้อมูลรถ" (สไตล์เดียวกับ "เพิ่มทะเบียนใหม่")
  - เลือกทะเบียน (dropdown รถทั้งหมด) → เลือกประเภทใหม่ (ใช้ `truck_type_th` labels: 6 ล้อ / 10 ล้อ / 10 ล้อ + หาง / 18 ล้อ / หางลาก) → ปุ่มบันทึก
- route ใหม่ `POST /check/mechanic/edit-vehicle`
  - guard `link.role == "mechanic"` (ไม่ใช่ → 403)
  - รับ `vehicle_id`, `truck_type`; โหลด Vehicle; เซฟ `truck_type` (และปรับ `vehicle_kind`: "tail" ถ้า truck_type เริ่มด้วย TRL, ไม่งั้นคงค่าเดิม) — เปลี่ยน **ถาวร** ใน DB
  - redirect กลับ `/check/mechanic?t=...&vehicle_id=<vid>` (โชว์รถที่เพิ่งแก้ พร้อมตรวจต่อ)
- **คนขับไม่มีปุ่มนี้** (`check_driver.html` ไม่แตะ)

### 3. ช่างเพิ่มทะเบียนหาง
- ใช้ `POST /check/add-vehicle` ที่มีอยู่แล้ว (auto kind=tail เมื่อ truck_type ขึ้นต้น TRL — มีโค้ดแล้ว)
- เพิ่ม UI add-vehicle ใน `check_mechanic.html` (ตอนนี้มีแต่ใน driver): `<details>` "+ เพิ่มทะเบียน (หัว/หาง)" ตั้ง `role=mechanic`, dropdown ประเภทใช้ labels ไทยรวม "หางลาก (8 ล้อ)"
- ไม่ต้องเขียน route ใหม่

### 4. ตรวจหางต่อจากหัว (คนขับ) — ไม่บังคับ ข้ามได้
ปัญหา: flow คนขับเดิมตรวจได้ทีละคัน ไม่มีคอนเซ็ปต์ หัว+หาง
แนวทาง (เบาสุด ใช้หน้าเดิมซ้ำ): หลังส่งตรวจหัวสำเร็จ → โชว์ "สะพาน" ถามว่าลากหางคันไหน

- `check_driver_submit` (POST) เดิม redirect ไป `?done=<n>` — **คงไว้** (จำนวนล้อที่บันทึก)
- `check_driver_form` (GET) เมื่อมี `?done=<n>` และยังไม่ได้เลือกหาง:
  - ดึงรายการหาง `Vehicle.vehicle_kind == "tail"` (active)
  - โชว์ panel เขียว "ตรวจหัวเรียบร้อย ✓" + dropdown "วันนี้ลากหางคันไหน?" + ปุ่ม "ตรวจหางต่อ ▸" และลิงก์ "ไม่มีหาง / เสร็จแล้ว"
  - "ตรวจหางต่อ" = form GET ส่ง `vehicle_id=<หาง>` กลับมาหน้าเดิม → เข้าสู่ flow ตรวจปกติของทะเบียนหางนั้น (ผัง TRL8)
  - "เสร็จแล้ว" = ลิงก์กลับ `/check/driver?t=...` เปล่า (ไม่มี done) → หน้าเลือกทะเบียนปกติ
- หัวกับหางบันทึกเป็น TireEvent แยกตาม `to_vehicle_id` ของแต่ละคัน (ไม่ผูกถาวร)
- ถ้าไม่มีทะเบียนหางในระบบเลย → panel โชว์แค่ "เสร็จแล้ว" (ไม่มี dropdown ว่าง)

## ข้อมูล/สคีมา
- **ไม่เพิ่ม/แก้ตาราง** — ใช้ `Vehicle.truck_type`, `Vehicle.vehicle_kind`, `TireEvent.to_vehicle_id` ที่มีอยู่
- ไม่ขึ้น SCHEMA_VERSION

## ความปลอดภัย/permission
- edit-vehicle: ช่างเท่านั้น (role guard) — คนขับแก้ข้อมูลรถถาวรไม่ได้
- add-vehicle: ทั้งคู่ได้ (เดิมเป็นแบบนี้ — คงไว้ เพราะคนขับเคย "เพิ่มทะเบียนใหม่" ได้อยู่แล้ว)
- ไม่กระทบ payroll/billing/เงิน

## Error handling
- edit-vehicle ไม่พบ vehicle_id → 400 "เลือกทะเบียนรถก่อน"
- truck_type ว่าง → ไม่เปลี่ยน (คงค่าเดิม) ป้องกันลบประเภทโดยพลาด

## Testing (TDD)
1. `POST /check/mechanic/edit-vehicle` role=mechanic เปลี่ยน 10W→6W สำเร็จ; role=driver → 403
2. edit-vehicle ตั้ง TRL8 → vehicle_kind กลายเป็น tail
3. edit-vehicle truck_type ว่าง → ค่าเดิมไม่เปลี่ยน
4. `check_driver_form` มี `?done=1` + มีหางในระบบ → HTML มี dropdown หาง + ปุ่ม "ตรวจหางต่อ"
5. `?done=1` แต่ไม่มีหางในระบบ → ไม่มี dropdown ว่าง โชว์แค่ "เสร็จแล้ว"
6. add-vehicle จากหน้าช่าง (role=mechanic) ประเภท TRL8 → สร้าง Vehicle kind=tail (ครอบ regression ของ flow ที่มีอยู่)

## Out of scope (ยืนยันกับโอแล้ว)
- ผูกหัว-หางถาวร (โอบอกใช้หางไม่ได้คันเดิมตลอด)
- รวมหัว+หางในหน้าเดียวเลื่อนยาว (จอเยอะ คนขับงง)
- บังคับเลือกหาง (ข้ามได้)
- คนขับแก้ประเภทรถ (เฉพาะช่าง)
