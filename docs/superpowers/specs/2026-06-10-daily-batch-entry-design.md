# Daily Batch Entry — หน้าคีย์งานแบบตาราง (แทน /daily/new)

วันที่: 2026-06-10 · สถานะ: อนุมัติโดยโอแล้ว (brainstorming session)

## ปัญหา

หน้า `/daily/new` ปัจจุบัน (`ProjectYK_System/app/templates/daily_form.html`) เป็นฟอร์มแนวตั้ง 6 กล่อง ~28 ช่อง ต้องเลื่อนจอ+ลากเม้าส์ทั้งหน้าเพื่อคีย์ 1 งาน แต่พฤติกรรมจริงของคนคีย์คือ **คีย์หลายแถวต่อรอบ** (งานทั้งวันของไซต์เดียว) แบบ Excel

`/daily/grid` ที่มีอยู่ใช้แก้แถวเดิมเท่านั้น — สร้างงานใหม่ไม่ได้

## ขอบเขต

- **ทำ:** หน้า `/daily/new` ใหม่เป็นตารางคีย์หลายแถว + endpoint `POST /daily/batch`
- **ไม่กระทบ:** หน้าแก้ไขรายตัว `/daily/{id}/edit` ยังใช้ `daily_form.html` เดิม (mode='edit')
- **ตัดออกเวอร์ชันแรก:** พรีวิว fuel surcharge ⛽ (คงไว้ที่หน้าแก้ไขรายตัว), paste จาก Excel ตรง ๆ

### หัวหน้า (ตั้งครั้งเดียว ใช้กับทุกแถวที่ยังไม่บันทึก)

- `work_date` (default วันนี้) + `site_code`
- จะคีย์วันอื่นต่อ: บันทึกชุดปัจจุบันก่อน แล้วเปลี่ยนวันที่ — ไม่มี per-row date override

### คอลัมน์ต่อแถว (ปรับตามไซต์ที่เลือกใน header)

### แผง ⋯ (ช่องใช้น้อย — เปิดเฉพาะแถวที่ต้องใช้ เป็นแผงย่อยใต้แถว)

สถานะงาน (status_code) · สถานะลา (leave_status) · น้ำมัน/ไมล์ (fuel_liter, fuel_amount, fuel_station, fuel_rate_km_per_l, mile_snapshot) · ใบแจ้งหนี้ (invoice_no, invoice_date) · ภงด.53 (wht_53) · หมายเหตุ (remark)

## Autocomplete + กัน unlinked records

- ช่องคนขับ/ทะเบียน/ลูกค้า = text input + autocomplete จาก master (employees/vehicles/customers ที่หน้าโหลดมาแล้ว ไม่ต้องยิง API ต่อช่อง)
- พิมพ์ตรงกับ master → ส่ง id, ช่องพื้น**เขียว**
- ไม่ตรง → ส่งเป็น raw field (driver_raw_name / plate_no_raw / customer_name_raw), ช่องพื้น**เหลือง** เตือนตั้งแต่ตอนคีย์ว่ายังไม่ลิงก์
- ทะเบียนหลัก กรอง `vehicle_kind != 'tail'` · ทะเบียนหาง กรอง `vehicle_kind == 'tail'` (ตามฟอร์มเดิม)

## คีย์บอร์ด

- Tab / Enter = ช่องถัดไป · Enter ที่ช่องสุดท้ายของแถว = สร้างแถวใหม่+โฟกัสช่องแรก
- Ctrl+D = ก๊อปค่าช่องเดียวกันจากแถวบน
- ปุ่มลบแถว (เฉพาะแถวที่ยังไม่บันทึก)

## การบันทึก (กฎเงิน — ตรวจย้อนกลับได้)

- ปุ่มเดียว "บันทึกทั้งหมด (N แถว)" → `POST /daily/batch` (JSON list ของแถว + work_date + site_code จาก header)
- **Backend ใช้ logic เดียวกับ `daily_save` เดิมทุกประการ** — refactor แยกส่วน apply-row ใน `main.py` (`/daily/new` + `/daily/{id}/edit` POST, บรรทัด ~959) ออกเป็น helper แล้วให้ทั้งฟอร์มเดิมและ batch เรียกตัวเดียวกัน ห้ามเขียน logic ซ้ำ
- Response ต่อแถว: `{ok: true, id}` หรือ `{ok: false, error/warnings}`
- ฝั่งหน้า: แถวผ่าน → ✓ เขียว + id, ล็อกไม่ให้แก้/บันทึกซ้ำ · แถวติด → ไฮไลต์แดง + ข้อความ, ข้อมูลที่พิมพ์คงอยู่ แก้แล้วกด "บันทึกทั้งหมด" ซ้ำได้ (ส่งเฉพาะแถวที่ยังไม่ ✓)
- แถวว่างทั้งแถว = ข้าม ไม่ถือเป็น error
- ทุกแถวใหม่: `source="manual"` เหมือนเดิม

### วิธีตรวจย้อนกลับ

1. นับแถว `/daily` ของวันที่+ไซต์นั้นก่อนและหลังบันทึก — ผลต่างต้องเท่าจำนวน ✓
2. ทุกแถวใหม่ work_date/site_code ตรง header, source="manual"
3. แถวเหลือง (raw) ต้องโผล่ในรายการ unlinked ตามปกติ ไม่หายเงียบ

## สิ่งที่ต้องระวังตอน implement

- `daily_save` เดิมมี logic จับคู่ driver/vehicle/customer หลังรับ Form — helper ที่แยกออกมาต้องครอบส่วนนี้ทั้งหมด ไม่ใช่แค่ assign ฟิลด์
- ฟอร์มเดิม (edit mode) ต้องยังทำงานเหมือนเดิมหลัง refactor — เทสด้วยการแก้งานเก่า 1 แถวแล้วดูค่าไม่เพี้ยน
- ไม่แตะ SCHEMA_VERSION (ไม่มีการเปลี่ยน schema)
