# ระบบตรวจสภาพยาง + ตรวจรถรายสัปดาห์ — Design Spec

วันที่: 2026-06-22
สถานะ: รอ implementation plan
โมดูล: `ProjectYK_System/app/` (ต่อยอด Maintenance/Tire เดิม)

---

## 1. เป้าหมาย

แทนนิสัยเดิม "คนขับถ่ายรูปมั่วๆ ส่งลงไลน์กลุ่ม" ด้วยการตรวจที่มีโครงสร้าง:
หนึ่งการตรวจ = หนึ่งบันทึกต่อรถ ผูกตำแหน่งยาง + รูป + สภาพ + (ความลึกจากช่าง) เก็บในระบบเพื่อโชว์/ดูย้อนหลัง

ผู้ใช้เป็น **lowtech** (คนขับ + ช่าง) → ต้องไม่มี username/password และกดทำงานได้ทันที

## 2. ขอบเขต (build แรก)

**รวม:**
- การเข้าถึงแบบ magic link (ไม่ login)
- Flow คนขับ: เลือกรถ → ผังยาง top-view → ถ่ายรูป + แจ้งสภาพต่อเส้น (ไม่วัด มม.) → ตรวจรายสัปดาห์ (น้ำมัน/ของเหลว/อุปกรณ์) → ส่งทั้งคัน
- Flow ช่าง: คิว "รอช่างวัด" รวมทุกคัน → เติมความลึก มม. ต่อเส้น; งานยาง (สลับ/ย้าย/ใส่อะไหล่/ระเบิด/รั่ว/ทิ้ง) จบในลิงก์
- หน้า office: gen ลิงก์ + ดูผลตรวจ/ภาพรวมต่อรถ (ต่อยอดหน้า `/maint/tires` เดิม)

**ไม่รวม (ใช้ของเดิมฝั่ง office):**
- การตั้ง master ยางครั้งแรก (tire setup grid เดิม `/maint/tires/setup`)
- การจัดการ Vendor/Part/ราคา
- OCR อ่านทะเบียน (เลือกจาก dropdown ก่อน — เป็น nice-to-have ภายหลัง)

## 3. การเข้าถึง — Magic Link (ไม่มี user/password)

- **office gen ลิงก์** จากใน MVP → ส่งให้คนขับ/ช่างทางไลน์
- ลิงก์ = signed token (ปลอมไม่ได้) + วันหมดอายุ (default 1 ชม. ปรับได้ตอน gen)
- **1 ลิงก์ = ใช้ได้หลายคัน/หลายงานจนหมดอายุ** ผูกกับ **บทบาท** (driver | mechanic) ไม่ผูกคันเดียว
- เปิดลิงก์ → พิมพ์ชื่อตัวเองกำกับ (เก็บเป็นหลักฐาน actor_name) → ใช้งานได้
- ลิงก์ตามบทบาท:
  - **driver** → เลือกรถ → ผังยาง + ตรวจรายสัปดาห์
  - **mechanic** → คิวรอช่างวัด + งานยาง

**ความเสี่ยงที่รับได้:** ลิงก์อาจหลุดในกลุ่มไลน์ในช่วงที่ยังไม่หมดอายุ → ใครได้ก็กรอกได้ บรรเทาด้วย ชื่อที่พิมพ์ + timestamp + รถ → trace ย้อนได้ และอายุสั้น

## 4. Flow คนขับ (lowtech — ไม่วัดความลึก)

1. เปิดลิงก์ → พิมพ์ชื่อ → เลือกทะเบียน (หัว/หาง) จาก dropdown → กรอกเลขไมล์ (ครั้งเดียว/คัน)
2. **ผังรถมองจากบน (top-view)** — ล้อวางตามตำแหน่งจริง สีบอกสถานะ:
   เทา = ยังไม่ตรวจ / เขียว = ถ่ายแล้ว / แดง = คนขับแจ้งมีปัญหา; มีตัวนับ "x/N เส้น"
3. แตะล้อ → แผ่นเด้ง (bottom sheet):
   - **ถ่ายรูป** — เส้นนอก 2 รูป (ด้านข้าง + หน้ายาง), เส้นใน 1 รูป (หน้ายาง) เลือกให้อัตโนมัติตาม suffix ตำแหน่ง; ปุ่ม "เพิ่มรูป" (แผล/จุดผิดปกติ) ได้เสมอ
   - **แจ้งสภาพ** = ปุ่มง่าย 3 ระดับ: ปกติ / น่าจะใกล้หมด / มีปัญหา (รั่ว/บวม/ฉีก) — **ไม่มีช่องตัวเลข มม.**
4. ต่อท้ายผังยางในหน้าเดียว = **การ์ดตรวจรายสัปดาห์** (น้ำมันเครื่อง/ของเหลว/อุปกรณ์) ใช้ `VEHICLE_CHECK_ITEMS` เดิม สถานะ ปกติ/ผิดปกติ/ชำรุด
5. กด "ส่งทั้งคัน" → ทุกเส้นที่ถ่ายแล้วแต่ยังไม่มี มม. เข้าคิว **"รอช่างวัด"**; เส้นที่แจ้ง "มีปัญหา" flag

## 5. Flow ช่าง (จบในลิงก์)

**A. เติมความลึก มม.**
- เปิดลิงก์ช่าง → **คิว "รอช่างวัด" รวมทุกคัน** (รายการเส้นที่คนขับถ่ายไว้แล้วยังไม่มี มม.)
- แตะเส้น → เห็นรูปที่คนขับถ่าย + สภาพที่แจ้ง → กรอกความลึกด้วย control:
  **ลากหมุดบนแถบสี + ปุ่ม ±0.5 + ปุ่ม ±0.1** (ค่าเริ่มต้น = ค่าครั้งก่อนของเส้นนั้น)
  ป้ายสถานะอัตโนมัติ: ดี (>4.5) / เฝ้าระวัง (1.6–4.5) / เปลี่ยนด่วน (≤1.6)
- บันทึก → เส้นนั้นออกจากคิว

**B. งานยาง (TireEvent ตรง)**
- เลือกรถ → เลือกตำแหน่ง → เลือกประเภทงาน:
  - สลับ/ย้ายตำแหน่ง (rotate) — เลือกตำแหน่งปลายทาง
  - ถอด + ใส่ยางอะไหล่ (unmount + mount)
  - ยางระเบิด/รั่ว — mark + ถ่ายรูป
  - ทิ้งยาง/ไม่ได้นำกลับ (scrap) — มีหมายเหตุ
- ทุกงานบันทึก `TireEvent` + รูป + ชื่อช่าง + mile

## 6. โมเดลข้อมูล (ต่อยอดของเดิม เพิ่มน้อย)

ใช้ `Tire` + `TireEvent` เดิม การวัดแต่ละครั้ง = `TireEvent(event_type="inspect")` (มี tread_before/after_mm, mile อยู่แล้ว)

**เพิ่ม field ใน `TireEvent`:**
- `photo_paths: str = ""` — รูปต่อเหตุการณ์ (comma-separated, relative path เหมือน DriverSubmission)
- `actor_name: str = ""` — ชื่อที่พิมพ์กำกับ
- `actor_role: str = ""` — driver | mechanic
- `condition_flag: str = ""` — คนขับแจ้งก่อนช่างวัด: ok | near | problem
- `pending_mm: bool = False` (หรือ derive: inspect ที่ tread_after_mm == 0 และ condition_flag != "") — สถานะ "รอช่างวัด"

> หมายเหตุ: เลือก derive คิว "รอช่างวัด" จาก event ที่มี condition_flag แต่ tread ยังว่าง แทนเพิ่ม bool ถ้าทำได้ชัดเจน — ตัดสินตอน plan

**โมเดลใหม่ 1 ตัว — `AccessLink`:**
- `id`, `token` (signed, unique, index)
- `role` — driver | mechanic
- `created_by`, `created_at`
- `expires_at`
- `revoked: bool`
- `last_used_at`, `use_count`
- `note`

**ส่วนตรวจรายสัปดาห์:** ใช้ `DriverSubmission(kind="vehicle_check")` เดิม แต่เดิม submission ผูก `employee_id` (จาก 登入 driver) — ต้องรองรับเส้นทาง magic-link ที่ไม่มี employee → เก็บ actor_name ใน data_json / field เสริม (ตัดสินตอน plan: เพิ่ม nullable employee_id หรือ field actor_name)

**Position map หาง:** ปัจจุบัน `TRL_L1/TRL_R1...` (เพลาละ 2 ล้อ) → ปรับเป็น 8 ล้อ (เพลาละ 4: นอก/ใน ซ้าย-ขวา) `TRL_LO1/LI1/RI1/RO1/LO2/LI2/RI2/RO2`

## 7. ตำแหน่งล้อ — ป้ายภาษาไทย (คนขับ/ช่างเห็น)

เก็บรหัสอังกฤษหลังบ้าน + map เป็นไทยตอนแสดง:

| รหัส | ป้ายไทย |
|---|---|
| FL / FR | ซ้ายหน้า / ขวาหน้า |
| RLO1/RLI1/RRI1/RRO1 | ซ้ายหลังนอก / ซ้ายหลังใน / ขวาหลังใน / ขวาหลังนอก (เพลาหน้า) |
| RLO2/RLI2/RRI2/RRO2 | …(เพลาหลัง) |
| TRL_LO1.. | หาง ซ้ายนอก/ซ้ายใน/ขวาใน/ขวานอก (เพลาหน้า) |
| TRL_LO2.. | หาง …(เพลาหลัง) |

ลำดับไล่ซ้าย→ขวา ตามที่ทีมระบุ: ซ้ายหน้า, ขวาหน้า, ซ้ายหลังนอก, ซ้ายหลังใน, ขวาหลังใน, ขวาหลังนอก (เพลาหน้า) แล้วทำซ้ำเพลาหลัง

**กฎนอก/ใน:** suffix `O` = เส้นนอก (2 รูป) / `I` = เส้นใน (1 รูป) / FL,FR = เดี่ยว (2 รูป)

## 8. ความถูกต้อง (กฎเงิน/ข้อมูล)

- ไม่กระทบ payroll/billing โดยตรง
- ผูก vehicle + mile → **เตือนถ้าเลขไมล์ใหม่ < ไมล์ inspect ครั้งก่อน** ของรถคันนั้น (กันกรอกผิด/สลับรถ)
- distance-since-last = ไมล์ปัจจุบัน − ไมล์ inspect ครั้งก่อน (คำนวณตอนแสดง ไม่เก็บ field)
- การลบ/แก้ event ของช่างควรเก็บประวัติ (append-only แนะนำ)

## 9. UI ที่ตรวจสอบกับผู้ใช้แล้ว (mockup ผ่าน)

- ผังรถ top-view หัว 10 ล้อ + หาง 8 ล้อ ล้อเป็นช่องแตะได้ตามตำแหน่งจริง — ยืนยันลำดับ/ตำแหน่งถูก
- Control ความลึก: ลาก + ±0.5 + ±0.1 + แถบสีสถานะ — ยืนยันใช้ (ฝั่งช่าง)
- การ์ดตรวจรายสัปดาห์ต่อท้ายผังยางในหน้าเดียว — ยืนยัน

## 10. คำถามที่เหลือสำหรับช่วง plan

- `DriverSubmission` ผูก employee_id (not null) — เส้นทาง magic-link ไม่มี employee จะปรับ schema ยังไง (nullable + actor_name)
- คิว "รอช่างวัด" = derive หรือเพิ่ม flag field
- หน้า gen ลิงก์อยู่ใต้สิทธิ์ไหนใน RBAC เดิม (admin/office)
