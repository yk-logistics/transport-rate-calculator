# LCB Petty-Cash AI — Accuracy Proof (ชิ้นพิสูจน์ความแม่น)

วันที่: 2026-06-18
สถานะ: design approved → implementing
เจ้าของโดเมน: โอ (พงษกาญจน์)

---

## 1. ปัญหา / ที่มา

งาน **เงินสดย่อย LCB** วันนี้พนักงาน (หมิว/แอดมิน) กรอกมือทุกช่องในชีต แล้วต้อง
คำนวณเอง: คนขับแต่ละคนใช้เงินไปเท่าไหร่ → เงินทอนเหลือเท่าไหร่ → ไปหักเงินเบิก
รอบถัดไป (ตัดรอบรายสัปดาห์ อา.–ส.). ช้าและเสี่ยงพลาด โดยเฉพาะขั้น "โอนเงินเสร็จ
แล้วต้องมานั่งลงชีต".

ความฝันปลายทางของโอ: **โอนเงินแล้ว AI กรอกให้เลย** (คนอนุมัติก่อนลง).

แหล่งข้อมูลที่ทำให้เป็นไปได้: กลุ่ม LINE **"Y.K. หัวลาก LCB"** ถูกเก็บลง
`line_archive.db` บน server แล้ว (archiver service เดิม) — ฝั่งบริษัทแจ้งโอนเป็น
pattern ชัด: `@<คนขับ> ค่าคืนตู้ค่ะ` + แนบสลิป.

## 2. เป้าหมายของชิ้นนี้ (scope แคบ)

ตอบ **คำถามเดียว**: *ถ้าให้ AI เดารายการเงินสดย่อยจาก LINE มันแม่นกี่ %*

นี่คือ **proof** ไม่ใช่ production. วัดความแม่นก่อนตัดสินใจลงทุนสร้างของจริง.

### สิ่งที่ทำ
1. อ่าน `line_archive.db` (server, read-only) — กลุ่ม LCB ช่วง 16/6/2026 เป็นต้นไป
   (ช่วงที่ archive ครอบคลุม).
2. ประกอบ "รายการเดาแบบมีหลักฐาน" ต่อ 1 การโอน:
   - **คนขับ** = ชื่อที่ถูกแท็กในข้อความแจ้งโอนฝั่งบริษัท
   - **รายการ** = จากข้อความ (ค่าคืนตู้ / ค่าล้าง / เข้าท่า / เงินเบิก / เงินวิ่งงาน …)
   - **ยอด** = อ่านจากรูปสลิป (ตอนพิสูจน์: Claude อ่านในเซสชันนี้)
   - **งาน** = จากข้อความคนขับก่อนหน้า (รับตู้/คืนตู้ที่ไหน, เลขตู้) ถ้าจับคู่ได้
   - **confidence** = 🟢 ครบ / 🟡 กำกวม / 🔴 ขาด (เช่น ไม่มีสลิป, ไม่ได้แท็ก)
3. ดึง **เฉลย** จากชีต "สดย่อย LCB" แท็บ `16/6/26-15/7/26` (gid 1033061850).
4. เทียบ → ออก **รายงานเดียว** ใน `reports/`:
   - แม่นกี่ % แยกตาม field (คนขับ / ยอด / รายการ)
   - ตารางเทียบทีละแถว: AI เดา ↔ เฉลย ↔ ตรง/ผิด
   - เคสที่ AI พลาด + เหตุผล (ไม่มีสลิป / แท็กกำกวม / OCR เพี้ยน …)

### สิ่งที่ "ไม่" ทำ (กัน scope บวม)
- ❌ เขียนกลับชีต / ปุ่มอนุมัติ
- ❌ service รันเอง / ตั้ง Claude API key
- ❌ หน้าใน MVP
- ❌ คำนวณเงินทอน → หักเงินเบิก (เฟสถัดไป ถ้าผลแม่นพอ)

→ ชิ้นนี้ **อ่าน + เทียบ + รายงาน** เท่านั้น. **ปลอดภัยกับเงิน 100%** เพราะไม่แตะ
ข้อมูลจริงเลย (ไม่เขียน DB, ไม่เขียนชีต).

## 3. สถาปัตยกรรม

```
[server line_archive.db]  --(read-only via SSH/Tailscale)-->  recon script
        |                                                          |
        | media (สลิป .jpg) ----- ดึงเฉพาะสลิปฝั่งบริษัท --------->  |
        v                                                          v
  ข้อความแจ้งโอน + สลิป  --->  ประกอบรายการ (guess)  <---  Claude อ่านสลิป (vision)
                                       |
[ชีต "สดย่อย LCB"] --(gspread RO)--> เฉลย  --->  เทียบ  --->  reports/<...>.md|json
```

หน่วยย่อย (แต่ละชิ้นทำงานเดียว เทสต์แยกได้):

| หน่วย | หน้าที่ | input | output |
|------|--------|-------|--------|
| `extract_lcb_events` | ดึงข้อความแจ้งโอน + สลิป + บริบทคนขับ จาก archive | DB path, group, date-from | list[CandidateEvent] |
| `guess_entry` | ประกอบ 1 รายการจาก 1 event (ใคร/ค่าอะไร/งาน/confidence) | CandidateEvent (+ ยอดจากสลิป) | GuessedEntry |
| `read_slip` | อ่านยอดเงินจากรูปสลิป | slip image path | amount, bank?, time? |
| `load_truth` | ดึงเฉลยจากชีต แท็บ 16/6-15/7 | sheet id, gid | list[TruthRow] |
| `compare_report` | จับคู่ guess↔truth, คิด % , เขียนรายงาน | guesses, truths | report file |

**Engine สลับได้:** `read_slip` เป็น interface เดียว — ตอนพิสูจน์ใช้ Claude (เซสชันนี้);
ภายหลังสลับเป็น Claude API / Qwen-9arm ได้โดยไม่แตะส่วนอื่น. (ดู
[[reference-server-no-gpu-llm]] — ห้าม self-host LLM บน .197).

## 4. ขั้นตอนทำงานจริง (สำหรับ proof นี้)

เพราะเป็น proof ไม่ใช่ service: รันเป็น script ทีละขั้น, Claude อ่านสลิปในเซสชันนี้
(ไม่ตั้ง API). ลำดับ:

1. `extract_lcb_events` → ออกไฟล์ events.json (ข้อความ + path สลิป) — ตรวจตาเองได้
2. ดึงไฟล์สลิปจาก server มาเครื่อง (เฉพาะที่ต้องอ่าน ~129 รูป)
3. Claude อ่านสลิป → เติมยอดลง events
4. `guess_entry` → guesses.json
5. `load_truth` → truth.json
6. `compare_report` → `reports/lcb_petty_ai_accuracy_<date>.md`

## 5. เกณฑ์สำเร็จ (success criteria)

ชิ้นนี้ "เสร็จ" เมื่อ:
- มีรายงานที่บอก **% ความแม่นของแต่ละ field** บนข้อมูลจริง 16/6+
- มีตารางเทียบทีละแถว ให้โอตรวจด้วยตาได้
- มีรายการ "เคสที่พลาด + เพราะอะไร" เพื่อตัดสินว่าเฟสถัดไปคุ้มไหม

**ไม่** ตั้งเป้าตัวเลข % ขั้นต่ำ — ตัวเลขที่ได้คือผลลัพธ์ที่ใช้ตัดสินใจ ไม่ใช่เป้าที่ต้องถึง.

## 6. กฎเงิน (ยึดตลอด)

- AI **เสนอ** เท่านั้น — ในชิ้นนี้ยังไม่มีการเขียนค่าจริงด้วยซ้ำ
- ยอดเงินมาจาก **สลิปเท่านั้น** — ไม่มีสลิป/อ่านไม่ชัด = 🔴 ไม่เดายอด
- คนขับมาจาก **ชื่อที่แท็ก** — กำกวม = 🟡 ตีธง ไม่เดามั่ว
- เทียบกับเฉลยจริงเสมอ ก่อนเชื่อว่าแม่น

## 7. เส้นทางอนาคต (บันทึกไว้ — ยังไม่ทำ)

ชิ้นพิสูจน์นี้เป็น **รากของทั้ง 3 แบบ** ไม่ว่าจะไปทางไหน:

| แบบ | AI ตื่นมาคิดตอน | ความแม่น | ค่าใช้จ่าย | ทำเมื่อ |
|-----|----------------|---------|-----------|---------|
| **A. ดูเป็นรอบ** | วันละครั้ง / สิ้นสัปดาห์ อ่านย้อนหลังทั้งวัน | แม่น | **ถูกสุด** | หลัง proof ผ่าน |
| **B. ดูทุกเหตุการณ์** | ทุกข้อความใหม่ | ≈ A | แพงกว่า A หลายเท่า | ไม่แนะ (ไม่เพิ่มแม่น) |
| **C. ดูแพลนครบวงจร** | มีหน้าลงแพลนใน MVP → AI จับคู่แพลน↔สลิป | แม่นสุด | ต้องสร้างหน้าแพลนก่อน | ปลายทาง |

ข้อคิดหลัก: **archiver เฝ้าให้ฟรีอยู่แล้ว** (เก็บทุกข้อความ 24 ชม. ไม่ใช้ AI).
ที่เปลืองคือ "เรียก AI คิดบ่อยแค่ไหน". อ่านย้อนหลังทั้งวันทีเดียว (แบบ A) แม่นพอ ๆ
กับดูสดทุกวินาที (แบบ B) เพราะตอนสิ้นวัน AI เห็นทั้งเส้น (เช้ารับตู้ → บ่ายโอน) ครบแล้ว.
ดูรายละเอียดที่ [[project-ai-watch-line-group]].

Productionize ภายหลังต้องใช้ **Claude API แยก** (จ่ายตามใช้) เพราะ pipeline ต้องรันเอง
บน server ไม่ใช่ผ่านแชทของโอ (pack Max/Pro เรียกจาก service ไม่ได้). ปริมาณ ~700
สลิป/เดือน = ค่า API หลักไม่กี่บาท–สิบกว่าบาท ไม่ต้องอัป Max.
